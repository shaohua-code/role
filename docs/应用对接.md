# 应用对接

> **本阶段不做业务接入联调。** 管理台「新项目接入」已下线；向导源码在 `frontend/src/views/_archive/integration/`。下文是将来业务项目接入时的契约备忘，不是当前交付目标。CORS 默认只放行管理台（`localhost:5175`）。

产品规则见 [产品需求](产品需求.md)。SDK 源码在仓库 `sdk/python` 与 `sdk/typescript`。

## 1. 一句话

业务项目用 **OIDC 授权码 + PKCE** 登录，用 **SDK 2.x** 调 `POST /api/v1/authorization/check`。**业务权限必须带可用 `data_scope`**，否则 SDK 失败关闭。

## 2. 接入步骤

1. 管理台（L1 / L3）创建租户（若无）→ 创建应用 → 保存 `client_id` / `client_secret` / redirect（secret 只显示一次）。
2. 在应用工作台登记业务权限码（应用自己的 `permission_namespace`）。
3. 系统创建应用时已自动放置 `app.admin` / `app.member`；业务角色另建。
4. 为应用角色（或成员所用角色）配置 **RoleDataScope**（常用 `self`）。缺策略 → `data_scope_policy_missing`。
5. 需要菜单 / 按钮时，在工作台维护资源树，并在角色「应用权限」里勾选节点。
6. 业务侧 OIDC：校验 `iss` / `aud` / `exp`；会话租户以 token 为准，**禁止信请求头租户**。
7. 引入 SDK 2.x：`IamAuthorizationClient` +（可选）`IAMFastAPI.require_permission` / Express `requirePermission`。
8. 受保护 API：`require(permission)`；列表用返回的 `data_scope` 过滤，**先 AND 租户隔离**。
9. 联调：有 scope 通过；缺 RoleDataScope 失败；跨租户 token 403。

## 3. 相对 1.x 的破坏性变化

| 旧行为 | 2.x |
|---|---|
| `include_data_scope` 默认 false，可能「有权无范围」 | 业务码必须可用 `data_scope`，否则 SDK 失败 |
| alias 未登记行为不一 | `permission_map` 未登记 → 启动失败 |
| 包版本 1.x | **major 2.0.0** |

管理面码不要求 data_scope。旧 `iam.*` 码已作废。

## 4. 包名与安装

| 语言 | 包 / 模块 | 安装 |
|---|---|---|
| Python | `iam_authorization`、`iam_oidc`、`iam_fastapi`、`iam_fastapi_auth`、`iam_permission_sync` | `pip install -e "sdk/python[fastapi,oidc]"` |
| TypeScript | `@iam-platform/authorization-client`（不要写已废弃的 `iam-sdk`） | 仓库 `sdk/typescript` 本地依赖 |

版本以 `sdk/python/pyproject.toml` / `sdk/typescript/package.json` 的 **2.0.0** 为准。当前以仓库源码路径安装为主，不含生产 npm / PyPI 发版流水线。

## 5. 权限清单同步

- **平台目录：** `GET/POST /api/v1/admin/permissions`（管理 JWT；只出管理面码）。
- **应用命名空间：** `GET/POST /api/v1/admin/applications/{application_id}/permissions`，或同路径挂在 `/api/v1/tenant-admin/...`。
- SDK：`IamAdminClient(api_base_url, application_id=...)`；未传 `application_id` 时走平台目录。
- 应用侧登记的权限固定为 `surface=business` + `requires_data_scope=true`。
- 只增不改状态；停用走管理台 PATCH status。
- 应用侧码必须属于该应用 `permission_namespace`，例如 namespace=`crud` → `crud.document.read`。

## 6. 在线判权

业务码不要再传 `include_data_scope: false`。省略该字段时 SDK 对业务码自动请求 scope。

```http
POST /api/v1/authorization/check
Authorization: Bearer <access_token>
Content-Type: application/json

{
  "tenant_id": "<uuid>",
  "application_id": "<uuid>",
  "permission_code": "crm.document.read"
}
```

期望：`allowed=true` 且 `data_scope.mode=any_of` 含合法 constraints。批量判定：`POST /api/v1/authorization/check-batch`（1–32 个码）。

调用时 tenant 必须等于签发 token 的 `tenant_id`；应用可省略（默认 token 对应应用），不可切换到别的应用。管理接口只用 IAM 管理会话，不能把 OIDC 客户端 token 当平台管理员凭证。

所有在线 IAM 授权请求必须有明确超时；SDK 默认 3 秒，超时或网络故障按 503 失败关闭，不得因此访问受保护资源。

RoleDataScope 示例：

```http
PUT /api/v1/admin/roles/{role_id}/data-scopes
{"policies":[{"permission_id":"<uuid>","scope_type":"self"}]}
```

管理台入口：应用工作台 → 角色 → 应用权限 → 数据权限。

## 7. 前端码、后端角色

| 侧 | 做法 |
|---|---|
| 登录 | `GET /auth/me` 一次返回用户信息 + `roles[]` + `capabilities` |
| 前端 | **只用 capabilities / codes 裁菜单与按钮**；不要把前端码当安全边界 |
| 后端管理 API | `ensure_roles` / `require_roles`（L1 `platform.admin` / L3 `tenant.admin@租户` / L2 `app.admin@应用`） |
| 业务细粒度 | SDK `require_permission` + `data_scope` |

过渡期：`ensure_management_permission(code)` 仍可用，内部已映射到角色门禁；新路由请直接写角色。

判权按作用域过滤：钉住 A 应用的角色在 B 应用的 `check` 中不入选；租户域角色对同租户任意应用生效。同一用户可同时持有多个角色，权限码按并集合并。

## 8. 应用资源树

面向应用的显式资源树：**菜单**（含 `path`、`icon`、`extra`）为枝干；**按钮**与**数据规则**挂在菜单下。角色经「应用权限 → 资源权限」勾选子集（服务端自动补齐祖先）。

管理面（`/api/v1/admin`，须具备该应用管理门禁）：

| 端点 | 说明 |
|---|---|
| `GET/POST /applications/{id}/resources` | 平铺清单 / 新建（编码应用内唯一；按钮与数据规则必须挂菜单） |
| `PATCH/DELETE /applications/{id}/resources/{rid}` | 编辑（可移动父级，环形 409）/ 删除（有子 409；级联回收授权） |
| `GET/PUT /applications/{id}/roles/{role_id}/resources` | 读取已勾选集合 / 全量替换（自动补祖先） |

消费端（业务前端用用户 token）：

```http
GET /api/v1/authorization/my-resources?client_id={client_id}
```

返回有效角色（直连绑定 ∪ 活跃用户组继承）资源授权并集的嵌套树，仅含 `active` 节点。`resource_type` ∈ `menu | button | data_rule`。`data_rule` 的过滤条件存于 `extra`，由业务端解释，**不替代** RoleDataScope。按钮 / 数据规则用 `code` 做前端显隐即可，树已按角色过滤；接口鉴权仍走 check。

## 9. 业务系统职责

- 校验令牌签名、签发方、受众、有效期和随机状态参数。
- 在服务端校验 API、数据和资源级权限。
- 请求上下文绑定用户 ID、租户 ID 和应用 ID。
- 把 `data_scope.any_of` 编译到自己的查询，每条分支都 AND `tenant_id`。
- 避免将客户端密钥、模型密钥或长期令牌放在浏览器。
- 敏感操作须在线授权或 introspection；只离线验签会接受直至 token 过期（当前 access token 默认 10 分钟）。

## 10. 旧接入拆除与明确不做

重新对接时：删除业务环境旧 client_id / 密钥 → 升级 SDK 2.x → 重跑权限同步与 RoleDataScope → 验证缺策略应失败。已下线试点（含 DeerFlow）不得沿用旧 client_id 或授权。
