权限编码作用域一级分组（平台 → 租户 → 应用）

轮次：P393 前置：P392 五域 27 码 / P390 收敛矩阵 / P389 目录页改版 状态：已批准实施（2026-10-28）

1. 背景与问题

P392 将管理面权限编码重建为三段式五域体系（platform / rbac / org / app / ops）后，权限编码目录页的统计卡带与授权弹窗的域导航都按功能域分组（01 平台 / 02 角色与授权 / 03 组织与成员 / 04 应用 / 05 资源与运营）。功能域是技术视角的划分，与管理者「这条权限码归哪一级用」的心智不一致：

  • 用户核验授权范围时，第一问题不是「这是哪个功能的码」，而是「这是平台的事、租户的事，还是某个应用的事」；
  • 租户管理员角色（L3）看不到平台域、应用管理员（L2）看不到平台与租户治理码（P390 收敛矩阵已在弹窗生效），但目录页仍把所有码平铺在功能域卡带下，作用域边界不可见；
  • 目录页命名空间筛选器的空态文案为「全部分组」，与「权限域」下拉并存，进一步混淆了「分组」概念。

产品决策：权限编码的一级分类从功能域改为作用域层级——一级「平台」、二级「租户」、三级「应用（业务码）」，功能五域降级为筛选维度。目录页与授权弹窗使用同一套分组口径。

2. 范围

项内容
P0 入口① 权限编码目录页（平台管理员）；② 角色授权弹窗（平台 / 租户 / 应用管理员配置角色权限时）
P0 动作按作用域（平台 → 租户 → 应用 → 业务码）浏览、筛选、定位权限编码；给角色配权时在收敛后的作用域组内勾选
完成证据目录页统计卡带按作用域显示且点击可筛选；授权弹窗域导航按作用域分组且与角色收敛矩阵一致
恢复路径作用域筛选可一键清除（点击「全部」卡或再次点击取消）；弹窗关闭即重置，不影响已保存授权
不做不改后端码表、判权逻辑、模板码集与任何 API 契约（纯展示层分组重构）；不做权限编码的新增/停用流程变更

3. 共享规则：作用域归属（唯一口径）

每个权限编码恰好归属一个作用域组，归属规则由 P383 已裁决的模板码集确定性推导，不逐码人肉裁定：

归属规则（按持有该码的模板角色推导） 仅 L1 模板持有 → 平台组；L3 持有且 L2 不持有 → 租户组；L2 模板持有（L3 必然同样持有，体现上级兼容）→ 应用组；catalog_namespace 非 platform 的码 → 业务码组（按命名空间再分组）。

按此规则，P392 的 27 个管理码归属如下（评审重点——如对个别码有异议请在此表上标注）：

作用域组数量权限编码语义
① 平台6 platform.overview.read、platform.tenant.read、platform.tenant.manage、platform.account.read、platform.account.manage、rbac.role.manage 租户与全局账号治理、平台总览、平台角色写——仅平台超管（L1）持有
② 租户6 org.read、org.manage、rbac.role.read、rbac.permission.manage、rbac.app_role.assign、ops.model.manage 组织架构、角色目录读、权限目录写、任命应用管理员、模型目录写——租户管理员（L3）持有而应用管理员（L2）不持有
③ 应用15 app.read、app.manage、app.secret.rotate、rbac.app_role.read、rbac.app_role.manage、org.member.read、org.member.manage、org.invite.manage、org.group.read、org.group.manage、rbac.permission.read、ops.model.read、ops.theme.manage、ops.audit.read、ops.authz.simulate 应用与成员日常管理——应用管理员（L2）持有，租户管理员（L3）全量兼容持有
④ 业务码动态 各应用命名空间自助登记的码（如 resume.resume.read、demoapp.workflow.run） 应用业务功能权限，按命名空间二级分组；绿场重置后当前为 0

验算：6 + 6 + 15 = 27 管理码全覆盖、零遗漏零重复；业务码数量随应用登记动态变化。授权权码（rbac.app_role.manage / org.member.manage / org.invite.manage / org.group.manage）分属应用组，P383「自定义角色禁持授权权码」规则不受分组影响。

4. 功能需求

FR-01
权限编码目录页：作用域统计卡带与分组展示

触发：平台管理员进入「权限编码」目录页。结果：统计卡带从功能五域改为作用域四卡，点击即筛选；编码列表按作用域分组呈现。

统计卡带

  • 卡带五张：00 全部（27 + 业务码 N，附活动数）、01 平台 6、02 租户 6、03 应用 15、04 业务码 N；每卡显示总数与启用数，编号沿用账本式样式。
  • 点击卡片即按该作用域筛选（再点取消或点「00 全部」清除）；与权限域下拉、命名空间下拉、搜索框叠加过滤。
  • 业务码卡在数量为 0 时保持可见但置灰不可点（传达「业务应用可自助登记」的概念位）。
DEMO · FR-01 统计卡带与分组列表（可点击）
组内排序：管理码按编码字母序；业务码组按命名空间分小块。停用码照常显示并由「状态」列表达，不因作用域分组隐藏。

筛选器修正

  • 命名空间下拉空态文案由「全部分组」改为「全部命名空间」，消除与作用域分组的概念冲突。
  • 「权限域」下拉保留功能五域（platform / 角色与授权 / 组织与成员 / 应用 / 资源与运营）作为第二级筛选维度；编码行「权限域 / 命名空间」列继续显示功能域名与命名空间，字段不变。
  • 表格列结构（P389 的 6 列）不变，仅行归属与分组次序随作用域口径调整。

异常与空态

  • 任一作用域组为空（除业务码概念位外目前不会发生）时该卡显示 0 且不可点，列表对应分组不渲染。
  • 多条件叠加无结果时显示既有空态文案「没有匹配的权限项」，并保留全部筛选条件可清除。
FR-02
授权弹窗：作用域域导航与收敛矩阵对齐

触发：管理员在角色管理 / 应用工作台打开「配置权限」弹窗。结果：左侧域导航一级改为作用域组，并与 P390 收敛矩阵天然对齐。

导航分组与收敛

  • 域导航组序：平台 → 租户 → 应用 → 业务码（业务码组内按命名空间二级分组）。
  • 收敛矩阵由「按功能域隐藏」改写为「按作用域组隐藏」，判权口径零变化：平台角色显示全部四组；租户角色隐藏「平台」组；应用角色隐藏「平台」「租户」两组，且业务码组仅显示本应用命名空间。
  • 历史已持有的越域码豁免隐藏（P390 既有哲学：可撤销、不静默剥夺），显示在其所属作用域组内；自定义角色授权权码禁选规则（P383）不变。
DEMO · FR-02 弹窗域导航随角色类型收敛（切换角色类型查看）
禁选样式示意：授权权码对自定义角色禁勾（琥珀标注），历史已持有越域码照常出现在其作用域组并可撤销。

状态与反馈

  • 每组头部显示「已选 / 总数」计数；已选摘要条、预览影响对比、sticky 操作条等 P389/P391 交付物不变。
  • 切换角色类型（弹窗按传入角色渲染）时组可见性即时变化；关闭弹窗重置全部展示状态。
  • 保存链路（勾选 → 预览 → PUT）报文与判权零改动：作用域分组仅是展示层重组。
FR-03
分组口径单一来源

目录页与授权弹窗的作用域归属必须共用同一份映射口径（前端共享常量，按第 3 节规则实现），禁止两处各自维护映射表。未来新增管理码时，按第 3 节归属规则推导其作用域组；规则无法覆盖的码（不应出现）须在登记时被拦截并显式归组，不允许落入「未分组」静默展示。

5. 交互细则

场景行为
作用域卡 + 功能域下拉叠加取交集（如「租户」卡 + 「资源与运营」域 = ops.model.manage 单条结果），空交集显示空态
搜索命中跨组仅高亮命中行，不自动收起其他作用域组（保持全局上下文）
业务码命名空间排序按命名空间名称字母序；同一命名空间内按编码字母序
弹窗窄屏（<760px）域导航降级为横滑 tabs（P389 既有行为），tab 名称使用作用域组名
主题自适应分组标识使用现有 token 变量，深浅主题跟随（P389 已建立的模式）

6. 边界与既有规则衔接

既有规则与本 PRD 的关系
P390 收敛矩阵（角色类型 → 可见域）改写为作用域组口径（见 FR-02），隐藏结果与现状等价：租户角色原隐藏【platform/业务/其他】五域 ≡ 新口径隐藏平台组 + 业务码组（业务码随应用，租户全域角色不配）；应用角色原隐藏【platform/其他】+ 码级黑名单 ≡ 新口径隐藏平台组 + 租户组（治理码 rbac.role.read / rbac.role.manage / rbac.permission.manage 分属租户/平台组，被组级隐藏覆盖）+ 业务码限本命名空间
P383 自定义角色授权权码禁选不变；授权权码位于应用组，禁选标注跟随码而非组
P388 功能域分组授权弹窗与目录页的一级分组被作用域取代；功能域保留为目录页筛选下拉与编码行域名展示
P391 提示降噪不回退：分组变更不新增大块提示，组头说明走既有轻量样式
后端 catalog_namespace / surface 字段零改动；作用域归属是展示层推导，不需要后端新增字段或接口

7. 验收要点

  • 目录页统计卡带为「全部 / 平台 6 / 租户 6 / 应用 15 / 业务码 N」，点击筛选与叠加过滤行为正确；27 码逐一归组与第 3 节表格一致。
  • 命名空间下拉空态文案为「全部命名空间」。
  • 弹窗以 L1 / L3 / L2 三种角色分别打开：L1 见四组；L3 无平台组；L2 仅应用 + 业务码（本命名空间），历史已持有越域码可见可撤销。
  • 保存授权后重新打开，勾选状态与保存前一致；预览影响、保存报文与改造前逐字节等价（同勾选集）。
  • 深浅主题与窄屏下分组样式无破损。
