PRD · PERMISSION GROUPING · P388 候选

权限编码按作用域分组

授权弹窗与权限目录的码域分区、筛选与业务码命名空间分组

深度：轻量迭代 状态：P0 已实施（P388，2026-10-28）；P1 待裁决 上游口径：PRD §3.1 三级角色作用域

01

背景与问题

权限目录现有 67 个编码（管理面 27 + 业务面 40）。授权弹窗（角色「配置权限」）把全部编码平铺在同一个滚动列表里：平台专属码（iam.tenant.*、iam.user.*）、租户域码（iam.organization.*）、应用域码（iam.application.*）与业务码（deerflow.*、crud.*）混排，管理员配权限时需要在长列表中滚动查找，且无法直观判断「这个码跟当前角色的作用域是否相关」。权限编码目录页（/permissions）已有命名空间筛选，但 iam 命名空间下 27 个管理码仍无域语义区分。

三级角色作用域的模型与码域边界已在《产品需求》§3.1 固化，交互原型（docs/prototypes/role-scope-design/）已验证过六组码域口径的用户可读性。本需求把这些口径落到授权与目录两个界面。

03

共享规则：码域分组（唯一口径）

全部界面使用同一张「码前缀 → 组」映射，与《产品需求》§3.1 三级作用域一致。本规则为唯一权威定义，两个界面直接引用，不各自维护。

组码前缀匹配语义
平台专属iam.tenant.*、iam.user.*、iam.platform.*、iam.role.manage仅平台角色（L1）可持
租户治理iam.organization.*、iam.permission.manage、iam.model.manage租户全域治理（L3 专属）
成员协作iam.member.*、iam.group.*、iam.invitation.*、iam.role.read、iam.permission.readL3 / L2 共有（授权权码含于其中）
应用域iam.application.*、iam.app_role.*应用配置与角色管理
模型 / 主题 / 审计iam.model.read、iam.theme.*、iam.audit.*、iam.authorization.simulateL3 / L2 共有的平台资源面
业务码非 iam. 前缀（按 catalog_namespace 二级分组：deerflow / crud / demo …）应用命名空间业务码，强制数据范围

映射仅服务于展示分组，不改变任何判权、可挂载性与保存校验（这些由既有后端规则负责：自定义角色禁持 4 个授权权码、应用角色命名空间校验、业务码强制数据范围）。前缀不匹配任何组的未来新码归入「其他」，置于业务码之前，避免静默丢失。

04

功能需求

FR-01 授权弹窗分组展示

触发角色管理 / 应用工作台 → 「配置权限」，弹窗加载全量活动权限目录时（平台侧含停用码只读展示）
分组规则码列表按共享规则的六组分区渲染：每组一个组头（组名 + 数量），组内排序保持现有「中文描述主行 + 等宽码副行」。组头可点击折叠 / 展开，默认全部展开；业务码组内部再按命名空间二级分组（组头为命名空间名，如 deerflow）
域筛选弹窗顶部码列表上方新增一排筛选 chips（全部 / 平台专属 / 租户治理 / 成员协作 / 应用域 / 模型主题审计 / 业务码），点选后仅渲染对应组；「全部」为默认。与既有搜索框叠加生效
禁选不变自定义角色的 4 个授权权码维持置灰禁选 + 组内警告；停用码维持「停用，仅可撤销」标注——分组不改变任何可选性
结果与状态选中集合、预览影响、保存流程完全不变；分组纯展示层，保存报文结构与后端契约零改动
空组与异常某组在当前目录下无码时不渲染该组（含筛选后为空的提示态）；搜索无结果时保留现有空态文案

FR-02 权限目录页权限域筛选

触发平台控制台 → 权限编码目录（/permissions），平台管理员浏览 / 启停编码
域筛选工具栏在「命名空间」筛选旁新增「权限域」下拉（全部 / 平台专属 / 租户治理 / 成员协作 / 应用域 / 模型主题审计 / 业务码），按共享规则映射过滤；与命名空间、搜索叠加生效
域标签「命名空间」列保持；为 iam 码行新增域标签（或并入现有列）展示所属组，业务码行显示其命名空间即已足够，不重复打标
结果与状态登记 / 启停 / 编辑行为不变；筛选仅影响列表呈现，不改变「权限编码为只读目录 + 受控启停」的产品定位

FR-03 口径一致性

规则两界面的组名、组序、组色必须与共享规则表逐字一致；未来新增码前缀时只允许修改共享映射一处（前端单一常量），两界面同步生效
禁止事项分组不得暗示授权语义（如不得把「成员协作」渲染为灰色不可选——可选性仍由角色 kind / 自定义状态决定）；不得在组头显示与判权无关的提示文案
