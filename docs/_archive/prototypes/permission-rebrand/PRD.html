01

背景与问题

CONTEXT

现行权限目录 67 码（管理面 iam.* 27 + 业务面 40）与四级角色体系在多轮迭代后暴露三类问题：

①命名不一致

role 与 app_role 语义易混、user 与 member 边界模糊、platform.overview / authorization.simulate 等「域.动作」式编码破坏三段式一致性。

②第一段无信息量

全部 iam. 前缀使菜单分组、授权分组、收敛矩阵都要靠第二段二次映射。

③历史数据混杂

多轮造数与调整后，角色目录与授权关系不再「样板干净」。

产品决策（已确认）：平台侧权限编码与角色体系推倒重写；历史数据绿场一键重置清零（DeerFlow 业务试点资产一并清零，之后按新体系重新登记）；UI（角色管理 / 权限编码页）按新体系重新设计。
