# 模型测试台页面设计与现行边界

> 目标：管理员能确认一个模型在指定范围内是否真正可调用，并用连续对话复现问题，查看可公开的思考输出、流式事件和诊断信息。现行 `/models/test` 为管理员受控测试通道；面向业务应用的统一代理网关仍未实施。实际接口见 `frontend/src/views/models/test/api.ts` 与 `backend/app/api/v1/admin/model_tests.py`，后续专项见[产品需求 §6.4.1](产品需求.md)。
>
> **原型预览：** [模型测试台-交互式原型](prototypes/模型测试台-交互式原型.html)（高保真可交互，全部数据为前端模拟；浏览器直接打开，含演示场景切换与深浅主题）。

## 1. 先回答什么问题

1. **目录通不通：** 模型是否启用、凭据引用是否可解析、部署是否可达、Provider 是否返回有效响应。
2. **应用能不能用：** 选定应用后，当前操作者是否有该应用访问关系，模型是否同时处于平台目录、租户下发和应用下发的有效交集。
3. **输出是否符合预期：** 对话正文、可见思考过程、工具调用、用量与耗时分别是什么；失败停在哪一环。

状态必须分开显示：`配置有效`、`授权可用`、`Provider 可达`、`本次生成成功`。只读目录或一次健康检查成功不能显示“模型已通”。未跑过的环节显示“未测试”，读取失败显示“无法判定”。

## 2. 入口与范围

- 不增加侧栏一级导航。在「模型治理」目录行操作中增加「测试」入口，进入 `/models/test?model_id=...`；应用工作台「模型」Tab 的已下发模型行也可进入，并携带应用上下文。具体路由以实施时现有路由配置核定。
- 页面头部显示模型展示名、稳定 ID、Provider/部署、活动状态、能力标签和当前上下文。应用上下文必须明确显示租户及应用；切换上下文立即清空本地会话和上次结果，避免把不同应用的结果混看。
- 两种测试模式：**平台连接测试**仅供具备超管范围及模型管理权限的操作者，验证受控部署/凭据/Provider，不表示业务应用已获授权；**应用对话测试**按当前登录操作者和所选应用逐次判权，只有三级下发交集有效才允许实际外呼。管理员不能在请求体中任填 `user_id` 冒充他人。
- 现行代码已有服务端凭据引用解析、固定连接探针与文本对话测试接口；目录存在或授权判定仍不能包装成真实“连通”，须由探针或对话调用的实际结果确认。

## 3. 页面布局

```text
页头  模型测试台 / 模型名                         [清空会话] [调试设置]
上下文  模式 [平台连接 | 应用对话]  租户/应用选择  模型选择  能力与状态
状态行  配置有效  授权可用  Provider 可达  本次生成成功   最近测试时间
------------------------------------------------------------------
对话区（主列）                         诊断区（次列，可收起）
用户/助手消息，流式输出                [思考过程 | 事件 | 请求与用量]
助手消息下：可见思考摘要/步骤入口       思考片段、工具事件、耗时、错误码
------------------------------------------------------------------
输入框  附件（仅支持时）                [停止] [发送]
```

桌面为对话主列 + 可调宽诊断次列；现行窄屏将诊断区改为按需展开的下方面板，输入区在对话卡底部可达，页面无横向溢出。复用现有管理台页头、按钮、表单、状态和主题 token；一页只有一个主要发送按钮。不要在主页面重复建侧栏。未选择模型时给出明确空态。

### 3.1 对话主列

- 用户与助手消息按轮次展示；正在生成时逐段出现，保留换行、代码块和复制操作。正文与思考输出是两条独立流，不混为一段助手回复。
- 多轮会话默认只存在当前浏览器内存，刷新或离开即清除；“清空会话”二次确认，切换模型、租户、应用或模式自动清空并取消在途对话。现行上下文只携带已完成的最近 10 轮且历史总长不超过 32000 字；可编辑本轮输入并重发，重发从该轮截断后续上下文，界面先提示。
- 发送时锁定该轮模型、上下文和调试参数；支持停止生成。停止后的答案标为“已中止”，不伪装成完成；允许复制本轮请求 ID 供排障。
- `vision` 才显示图片上传；`json_output` 才显示 JSON 模式；`tool_calls` 才显示工具调用调试。首版先做纯文本对话与流式输出，其他能力按适配器真实支持逐项开放，不用目录标签代替能力实测。

### 3.2 思考过程与事件

- 诊断区「思考过程」只渲染 Provider **实际返回且允许展示**的 reasoning 摘要、可见片段或步骤。每段标明来源、接收顺序和时间；支持流式追加、折叠和复制。`reasoning` 标签仅表示可启用深度思考，`thinking_output` 才表示预期可能返回可见过程，两者不等同。
- 未返回思考内容时说明当前状态；现行实现区分尚未调用、生成中、调用未完成、模型未声明能力和 Provider 未提供。参数关闭与适配器未映射属于后续可扩展分类。不得根据最终答案猜测或编造步骤，也不得承诺展示模型内部完整推理。
- 「事件」按时间线展示请求创建、授权判定、预留、Provider 连接、首个 token、正文/思考片段、工具调用、完成/停止/失败；单项可展开脱敏后的结构化数据。事件顺序按服务端序号，重连不能重复插入。
- 「请求与用量」显示实际生效参数、部署版本、请求 ID、HTTP 状态类别、首字耗时、总耗时、输入/输出 token、Provider 返回的推理 token（若有）、用量质量 `actual/estimated/unknown` 及费用估算；未知值显示“未知”，不能显示 0。原始响应仅提供脱敏后的允许字段，不能回显凭据或内部令牌。

### 3.3 调试设置

现行抽屉只提供受控出口实际转发的 temperature、top_p、最大输出 token 和系统提示词；控件带合法范围、默认值与“恢复默认”，关闭后重置未提交修改。流式开关、深度思考力度、JSON 格式要求、工具调用等需待适配器真正支持后开放，不能只根据目录能力标签显示可用控件，也不能静默忽略用户提交的参数。

## 4. 交互与判定

| 场景 | 页面反馈 | 是否外呼 Provider |
| --- | --- | --- |
| 初次打开/未选模型 | 四项状态均为“未测试”；提示选择模型 | 否 |
| 模型停用、租户或应用未下发 | “授权不可用”并指出缺失的层级；发送禁用 | 否 |
| 凭据引用缺失/无法解析 | “配置失败”；显示可操作的错误类别，隐藏引用原文 | 否 |
| Provider 连接超时、TLS/网络错误 | “Provider 不可达”；记录阶段、耗时和请求 ID | 尝试过 |
| Provider 返回 401/429/5xx | 分类显示“凭据拒绝/限流/上游故障”，429 展示可用的重试等待 | 尝试过 |
| 有正文、没有可见思考 | 对话成功；思考区说明未返回，不报页面故障 | 是 |
| 流式中断/用户停止 | 保留已收到片段，状态“未完成/已中止”；用量未知则待核对 | 可能已外呼 |
| 读取诊断失败 | 错误提示与重试；保留已成功显示的结果 | 不自动重发 |

“测试连接”使用固定、短小的服务端探针并给出分阶段结果；“发送”是真实对话调用。两者分别计数和记录，不能把连接测试成功当作本次生成成功。测试请求也可能产生 Provider 费用；发送前显示该提示，限流、超时和输出上限由服务端强制。

## 5. 原始服务端契约草案（现行路径见代码）

- `POST /api/v1/admin/model-tests/connection`：平台连接测试，输入仅为已登记的模型/部署 ID；服务端读取受控凭据引用并外呼固定探针，返回 `test_id`、各阶段状态、耗时、错误类别。不得接受浏览器传入任意 URL、凭据或 Header。
- `POST /api/v1/admin/model-tests/conversations`：应用对话测试，输入模型 ID、已选应用 ID、消息和白名单调试参数；服务端从管理会话确定操作者与可用上下文，外呼前重验活动模型、三级下发及操作者的应用访问。返回会话 ID 和请求 ID；会话仅用于短期流式传输，不持久化正文。
- `GET /api/v1/admin/model-tests/conversations/{id}/events`：SSE 事件流，含单调 `sequence`、`request_id`、`type`、`timestamp`、`payload`。事件类型至少有 `status`、`reasoning_visible`、`answer_delta`、`tool_call`、`usage`、`error`、`done`。断线重连通过最后序号去重；授权或上下文变化立即停止后续外呼。
- `POST /api/v1/admin/model-tests/conversations/{id}/cancel`：停止当前调用并终结流；响应明确取消是否已到达 Provider，账目进入正确结算或待核对状态。
- 错误统一返回稳定 `code`、`stage`、安全提示、`request_id` 和可选 `retry_after_seconds`；不返回上游原始异常正文。实际路径、SSE 形状与 Provider 适配能力须在 M0 盘点后定稿并写入 OpenAPI。

连接/对话请求走服务端受控出口，复用未来网关的身份、授权、路由、预留和结算能力；不能由浏览器直接请求 Provider。测试流量标记 `source=model_test`，账目与普通业务流量可区分但不漏计。前后端都不能记录提示词、回复、完整思考内容、密钥或令牌到普通日志/审计；审计仅记操作者、模型/应用、动作、结果、请求 ID 和时间。不要把原始对话持久化到 IAM 数据库。

## 6. 权限与实施顺序

- 平台连接测试复用超管范围及 `button.models.manage` 的管理边界；实施时应单独审查“测试”是否需要更细按钮码。应用对话测试建议新增 `button.models.test`（最低应用级）并在 `menu.models` 下配置，同时要求目标应用有效访问和三级下发；按钮隐藏与后端逐请求判权必须一致。新码只是提案，当前 `MENU_CATALOG`/`BUTTON_CATALOG` 中不存在。
- 先完成 M0 对端能力/凭据/出口盘点，再接服务端测试通道；先验收连接探针与错误分类，再开放单轮/多轮流式对话和可见思考，最后补视觉/工具/JSON 模式。没有真实 Provider 与账目核对前，不能把页面标记为端到端完成。
- 本文不改变当前 `MODEL_QUOTA_ENFORCEMENT_ENABLED=false`、现有 `my-models` 契约或 DeerFlow 范围。

## 7. 验收清单

1. 使用真实 Provider 分别验证连接成功、凭据错误、网络超时、429、5xx；每次能定位阶段和请求 ID，浏览器拿不到上游密钥。
2. 两租户/两应用/两用户权限矩阵覆盖：未下发、回收、停用、无应用访问及跨应用篡改均在外呼前拒绝；管理 UI 隐藏入口不能替代后端拦截。
3. 对支持与不支持 `thinking_output` 的模型各做流式/非流式调用；仅返回真实可见片段，缺失原因清晰，正文与思考不串流。
4. 多轮、重发、停止、断流重连、切换上下文、刷新清空均符合页面状态定义；未完成用量不显示为零。
5. 测试调用有独立来源标记与可信 usage；核对实际请求数、token、费用估算和中断后的待核对项，配额开关仍保持原状态。
6. 桌面与 375px 窄屏、浅/深主题、键盘与读屏检查通过；无页级横向溢出，诊断区与输入区可达。

**验证记录口径：** 文档完成只算“设计完成”；接口/页面源码、隔离或 mock 验证、目标环境 Provider 验收应在实施时分别记录。
