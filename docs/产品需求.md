# 统一身份与权限管理平台产品需求

本地启动见 [项目启动](项目启动.md)，部署门禁见 [部署与运维](部署与运维.md)，业务接入契约见 [应用对接](应用对接.md)。历史改动见根目录 [CHANGELOG.md](../CHANGELOG.md)。

**本阶段范围：** 只维护 IAM 管理台与绿场后端；**不做**业务项目接入联调，**不做** DeerFlow。公开注册与模型配额 enforcement 默认关闭。

## 1. 产品概述

### 1.1 定位

统一身份与权限管理平台（IAM）由统一登录中心和管理后台组成。平台统一管理身份、应用、组织、角色、权限策略、登录主题和审计；业务系统在自己的服务端执行授权结果，并负责本系统的业务数据访问控制。

### 1.2 目标

- 用户用一个账号登录多个已授权业务系统。
- 管理员在统一后台管理租户、应用、用户、组织、角色和权限。
- 每个接入应用可配置独立登录页主题。
- 业务系统基于统一身份和授权规则控制功能、数据与模型访问。
- 登录、授权变更及管理操作可查询、可审计。

### 1.3 设计原则

1. **认证集中，业务授权落地：** 平台提供可信身份和授权策略，业务服务端负责执行。
2. **默认拒绝：** 未明确授权的应用、接口、数据和模型调用均拒绝。
3. **租户隔离：** 租户是数据隔离边界，不能依赖前端传入的租户标识保障安全。
4. **最小权限：** 角色仅获得完成工作所需权限。
5. **看得见才能配：** 目录不出现操作者没有的权限，也配不进去。
6. **可扩展接入：** 采用标准认证协议和稳定的权限编码，避免绑定单一业务项目。

## 2. 范围

### 2.1 本期包含

- 用户登录、登出、密码重置；公开注册默认关闭。
- 租户、应用、用户、组织、用户组、成员邀请。
- OIDC 授权码登录；回调地址白名单；每应用登录品牌。
- 管理台浅色 / 深色 / 跟随系统、品牌主色、密度、可折叠侧栏。
- 三管理员平台角色（授权范围：超管 / 租户级 / 应用级，只能向下）+ 应用成员与应用角色；管理面唯一权限目录 = 「菜单 → 按钮」树；业务码数据叶子保留。
- 应用资源树（菜单 / 按钮 / 数据规则）与业务码目录仍走应用工作台，不与管理面合树。

- 完整模型代理网关、供应商账单结算。
- 允许管理员上传任意 HTML / JavaScript / CSS 并在登录页执行。
- 把认证、授权、审计拆成多个独立微服务。
- DeerFlow / 其他业务项目接入联调；管理台「新项目接入」向导（只读「项目对接指南」只复述契约，不算联调）。
- MFA、企业 SSO、目录同步、公开注册上线、配额 enforcement 上线。

## 3. 角色与权限

### 3.1 两套目录、两类角色

平台管平台，应用管应用。**不要**按库表 `roles.kind`（platform / tenant / application）理解成三类产品角色。

| | 平台权限 | 应用权限 |
|---|---|---|
| 管什么 | IAM 管理台：租户、组织、用户、邀请、平台角色、审计、主题、模型账本 | 某个业务应用：业务码、菜单、按钮、数据规则 |
| 挂在哪 | 高级管理 → 平台角色（菜单→按钮树 + 授权范围） | 应用工作台：权限编码 / 资源树 |
| 挂给谁 | 只挂给平台角色 | 挂给该应用的应用角色 |
| 禁止 | 把业务码挂给平台角色；把高于角色授权范围的节点挂进去 | 挂外应用业务码；挂操作者看不见的管理码 |

| | 平台角色 | 应用角色 |
|---|---|---|
| 有哪些 | 三个管理员模板 + 应用成员模板 + 自定义平台角色 | 钉住应用且 key 不在模板里的自定义角色（如财务、只读） |
| 挂什么 | 只挂「菜单→按钮」树节点 | 本应用业务码 / 菜单 / 按钮 |
| 出现在哪 | 高级管理 → 平台角色 | 应用工作台 → 角色 |

同一人可同时持有平台角色和应用角色；生效权限按角色并集，互不串租户、互不串应用。

### 3.2 三管理员 + 应用成员（授权范围只能向下）

层级：超管 > 租户管理员 > 应用管理员（都不能向上兼容，只能向下）。每个平台角色带**授权范围**（`roles.scope`）：

| 模板 key | 名称 | 授权范围 | 数据边界 |
|---|---|---|---|
| `platform.admin` | 平台超级管理员 | 超管 super | 平台所有内容可见；建删租户；任命租户管理员 |
| `tenant.admin` | 租户管理员 | 租户级 tenant | 当前用户**所有租户**的数据；本租户全部应用；任命应用管理员 |
| `app.admin` | 应用管理员 | 应用级 app | 当前用户**所有应用**的数据；管 N 个应用 = 绑 N 个应用；不能任命应用管理员 |
| `app.member` | 应用成员 | 成员 member | 零管理权限，仅表示业务侧属于该应用 |

规则：

- **范围只能向下：** 操作者只能创建 / 编辑 / 绑定授权范围秩 ≤ 自己的角色；应用级任命不了应用管理员（租户级能力）。
- **可见性收口不变式（2026-11-11 越权收口）：** 任意角色配置入口（角色列表 / 角色字典 / 用户分配角色 / 邀请选角色 / 用户组挂角色 / 新建克隆范围下拉）可见与可选的集合 ⊆ 操作者范围秩以下的角色 ∩ 自身数据边界；`roles.scope` 空值按推导口径（模板 key → 模板范围；钉应用 → 应用级；其余平台角色 → 租户级）参与秩过滤，不得旁路。
- **节点授权下限（min_scope）：** 每个菜单/按钮节点带下限（如 `button.tenants.manage` 仅超管、`button.models.manage` 仅超管、`button.models.distribute` 需租户级、`button.users.manage` 需租户级）；**配置角色权限弹窗中，节点授权下限高于被配角色当前范围的整节点不渲染**（含超管操作者视角）——需要更高范围的能力先调升角色范围，树随之展开；范围调低时自动剔除超出新范围的已勾选项并提示。
- **数据边界：** 列表与查询按操作者绑定的租户 / 应用过滤——超管全域；租户级限其所有租户；应用级限其绑定的应用（含 `app.member` 绑定即「属于」）。
- 应用创建 / 删除仍限超管与租户级；`app.member` 不能配权、不能新建角色。
- 没有独立「审计人员」角色；审计接口挂在具备 `menu.audit` 节点的管理角色上。
- 多应用管理员（`apps.admin`）模板已并入应用管理员；管 N 个应用 = 用户绑定 N 个应用。

前端 capabilities：`platform_codes` 只含菜单/按钮节点；顶层 `scope` 为操作者授权范围。

### 3.3 管理面唯一权限目录：菜单 → 按钮树

权威实现：`backend/app/services/permission_kinds.py`（`MENU_CATALOG` / `BUTTON_CATALOG`，节点带 `min_scope`）。**旧 27 个五域接口码与数据码目录已删除**；「权限编码」页面已下线，目录由种子固定，不再开放登记。

树形 = 现网侧栏（运营总览 / 身份与组织 / 应用与权限 / 高级管理 / 平台治理 / 审计与验证）。菜单下挂按钮，**菜单按钮自由搭配**勾选；只勾菜单不勾按钮 = 侧栏能进、写按钮不可见。判权单元就是节点编码本身：

- **菜单节点管侧栏与读接口：** `menu.*` → 导航裁剪 + 对应列表接口判权。
- **按钮节点管页内写操作与写接口：** `button.*` → 主写按钮显隐 + 对应写接口判权。
- **授权范围管数据边界与能力天花板：** 角色上的范围下拉（超管 / 租户级 / 应用级）+ 节点 `min_scope` 双闸。

按钮节点按页收口，例如 `button.users.manage`、`button.apps.secret`、`button.authz.simulate`。模板角色按种子固定节点集生效；自定义角色按勾到的节点 + 所选范围生效。

### 3.4 配权模型

| 层 | 名称 | 一句话 | 用在哪 |
|---|---|---|---|
| ① | 菜单→按钮树 + 授权范围 | 唯一管理面权限目录；范围决定数据边界与天花板 | 侧栏认菜单节点；写按钮与写接口认按钮节点；数据过滤认范围 |
| ② | 角色挂节点 + 用户配角色 | 用户可多角色；生效 = 并集 | 谁能管什么 / 业务身份是谁 |
| ③ | 应用资源树 + 业务码 | 按应用的菜单 / 按钮 / 数据规则树 | 业务端 `my-resources` 渲染导航与按钮 |

防改错：

- **范围不能向上：** 应用级看不到租户级数据，租户级看不到全域；上级能力只能向下继承。
- **看得见才能配：** 新增勾选必须落在操作者已有节点集合内；看不见的节点不出现、也配不进去。
- **业务面不变：** 应用工作台业务码仍强制 data_scope 叶子；资源树不替代接口鉴权。

### 3.5 日常怎么配

1. **平台角色**在高级管理 → 平台角色：新建/编辑时选**授权范围**（下拉：超管/租户级/应用级，只能选 ≤ 自己的范围），并在「菜单→按钮」树里自由勾选。
2. **应用角色**在应用工作台 → 角色行「应用权限」：资源权限（挂码 + 资源树）与数据权限同一抽屉（本轮保持不变）。
3. **配置成员**在角色行打开；「增加成员」从本租户成员多选绑定，自动补 `app.member`。给用户多选角色也可走用户管理。

排障顺序：用户有没有角色 → 角色有没有勾节点 → 角色授权范围够不够 → 租户 / 应用上下文是否对。

### 3.6 用户绑定与业务数据范围

**用户绑定（用户管理）：** 创建用户时三类多选绑定——

- **绑定租户（必选，默认选中一个）**：逐租户写 `TenantMembership`；
- **绑定组织（可选多选）**：写 `MembershipOrganization`（组织必须属于所选租户，每租户首个为主组织）；
- **绑定应用（可选多选）**：自动补该应用的 `app.member` 模板角色。

**业务数据范围（应用侧，本轮保持不变）：** V1 支持 `tenant`、`self`、`organization`、`organization_tree`、`selected_organizations`。登记强制范围的业务码自动生成 5 个 `kind=data` 叶子；`evaluate_access` 在业务码命中后校验数据码 / `RoleDataScope`。`POST /authorization/check` 返回的 `any_of` 只是可信过滤条件，业务服务须编译进自己的 SQL / 检索。

5. 平台治理：租户、登录主题、模型治理 / 模型用量
6. 审计验证：审计日志、鉴权模拟

应用工作台：左树顶部「新建应用」；租户 / 应用节点右侧「⋯」也可新建，其余为编辑 / 密钥 / 受信 / 启停 / 删除。选中后右 Tab 为角色 / 权限编码 / 资源 / 模型。角色行操作「应用权限」「配置成员」。
组织工作台：左树顶部「新建组织」；租户 / 组织节点右侧「⋯」也可新建下级，其余为负责人 / 启停 / 删除。选中后右 Tab 为成员 / 用户组。

### 4.2 统一登录中心

登录、注册（默认关闭）、忘记密码、邮箱验证（短信通道暂不建设）、授权确认、错误 / 锁定 / 服务异常提示。

## 5. 核心流程

### 5.1 新应用（管理台侧）

1. L1 / L3 创建应用，填写标识、名称、至少一个登录回调。
2. 配置登出地址与来源域名白名单。
3. 配置 Logo 与登录主题并发布。
4. 系统自动放置 `app.admin` / `app.member`；在工作台登记业务码、资源树与应用角色。
5. 为业务权限配置 data_scope，给成员绑角色。
6. 业务系统按 [应用对接](应用对接.md) 接入 OIDC 与 check。

### 5.2 登录

1. 用户从业务系统发起登录，跳转统一登录中心。
2. 登录中心按应用加载已发布主题，校验凭据与账号状态。
3. 检查用户是否具有该应用访问权限。
4. 返回授权码至已登记回调；业务服务端换令牌并校验签名、签发方、受众和有效期。
5. 业务系统建立自己的会话，后续权限在服务端执行。

### 5.3 登录主题发布

选择应用 → 改 Logo / 背景 / 颜色 / 布局 / 文案 → 桌面与移动预览 → 保存草稿并发布。`show_register` 只控制视觉，不能开通注册。

## 6. 功能需求

### 6.1 用户与账号

- 全局身份：`active | disabled | locked`。登录、管理 API 和 OIDC 均只允许 `active`。不得把「离职」作为全局状态。
- 租户成员：`active | disabled | departed`。`disabled` 可恢复并保留角色；`departed` 清角色 / 组 / 组织。用户管理支持管理员直加租户（新建或恢复 disabled / departed 关系）、彻底删除成员关系（记录与该租户角色 / 组 / 组织一并移除，不保留历史；不能删除自己的成员关系），离职成员也可直接重新加入，不再强制重走邀请。
- 全局停用 / 锁定递增 `auth_version`、撤销 refresh session、消费未兑换 code / consent，同事务审计。管理员不能操作自己。
- 用户标识全局唯一；邮箱按验证状态管理；手机号字段保留但暂不建设短信通道。
- 密码不得明文或可逆保存。会话列表不展示设备名 / UA / IP；未申请 `offline_access` 的短 token 不能按会话 API 撤销。
- 公开注册默认关闭。若将来开放：须邮箱 OTP 两屏、独立注册密钥、consumer 租户、普通默认角色、政策链接与 SMTP；客户端不得提交 tenant / role / 管理员标志。新账号不因通过身份验证就取得跨组织数据。

### 6.2 租户、应用、组织

- 租户：创建、启停；停用后拒绝该租户新登录和令牌刷新。删除采用停用或归档，避免误删审计。
- 应用：至少一个登录回调、最多 20 个；回调默认仅 HTTPS（localhost HTTP 限本机开发），内网 HTTP 部署可由运维配置 `IAM_ALLOW_INSECURE_REDIRECT_URIS=true` 放行；创建后租户、Client ID、回调白名单只读。密钥明文只展示一次。停用后新的登录授权必须失败。创建 / 删除仅 L1 / L3；L2 只能改钉住的应用。
- 组织：租户内部门树；删除前检查成员及下级。用户组可继承角色。

### 6.3 应用、密钥与主题

- 回调必须与白名单精确匹配，不允许通配。Back-Channel Logout 与模型网关地址为服务端间令牌传输，不受放行开关影响，始终要求 HTTPS。
- 客户端密钥仅用于服务端，不得发给浏览器。
- 管理台外观与应用登录品牌分开：管理台用 ConfigProvider + CSS 变量，不接受任意 CSS / HTML / JS。登录主题图片限制格式与大小，数据库只存元数据和地址。

### 6.4 模型目录与分发

**平台模型目录（超管维护）：** 超管维护平台支持的模型全集（key、provider、显示名、能力标签、单价、RPM/TPM、凭证引用）；凭证只存外部引用，不回读、不下发。**能力标签为标准集**（`chat` 对话 / `reasoning` 深度思考 / `thinking_output` 思考过程输出 / `tool_calls` 工具调用 / `json_output` JSON 输出 / `vision` 视觉 / `embedding` 向量嵌入），前端勾选配置、后端白名单强制校验；目录写操作仍由 `button.models.manage`（仅超管）收口。

**三级下发（可见性唯一口径）：**

- 超管将平台模型**下发**给租户；租户管理员（持 `button.models.distribute`，节点下限租户级）将**本租户已收到**的模型下发给应用并回收；应用管理员对本应用模型清单只读。
- 应用可见模型 = 平台目录 ∩ 租户下发 ∩ 应用下发；租户可见 = 平台目录 ∩ 租户下发。下发关系即授权唯一依据，业务码 / 应用资源树不参与模型判权；`/authorization/check` 的 `model.invoke` 调用前检查按同一口径判定（活动模型 + 活动租户下发 + 活动应用下发 + 用户对目标应用的有效访问关系）。
- 平台目录行统一归属平台租户（slug=platform）；所有按 ID 的目录 / 下发操作强制校验该归属，非平台目录行与不存在同样按 404 处理。
- 租户只能从已收到范围内勾选，无法越权（范围只能向下）。下发可回收，回收为**软失效**（保留关系供恢复与审计）；目录删除仍受用量账目阻塞，提示走停用；停用平台模型 = 全链路立即不可见。
- 下发 / 回收 / 状态变更记审计，与写操作同事务。

**业务消费契约：** 业务应用以用户 token 调 `GET /api/v1/authorization/my-models?client_id=` 获取本应用可见模型（契约见 [应用对接](应用对接.md) §9）；清单范围绑定服务端验签的 token 应用身份，`client_id` 仅作一致性校验，跨应用查询拒绝且不返回目标应用任何模型字段。IAM 只管目录与授权，真实调用凭证由业务应用自持（凭证不进入 IAM 响应与浏览器）；将来建模型代理网关后可演进为平台代管凭证，下发关系与用量账本复用。租户 / 应用级限流覆盖为规划项，P0 沿用目录级 RPM/TPM。

**用量账本：**

- 受信网关用 `IAM_MODEL_USAGE_API_KEY`（至少 32 字符）上报；不存 Prompt 或模型响应正文。
- `MODEL_QUOTA_ENFORCEMENT_ENABLED` 默认 false。预留到期后进入人工核对队列，不自动收费或释放。
- 费用按目录单价估算，未维护价格记为未知；当前无币种字段、无失败原因字段。

### 6.5 审计

记录登录成败、登出、密码重置、账号锁定、用户 / 应用 / 角色 / 主题 / 模型相关变更。不记录密码、完整令牌、客户端密钥或模型密钥明文。只提供查询，不提供修改和删除。

## 7. 页面关键状态

| 页面 | 关键状态 |
|---|---|
| 登录页 | 加载中、输入错误、账号锁定、服务异常、数据库待迁移 |
| 运营总览 | 空数据、加载失败、无查看权限 |
| 应用工作台 | 未选应用、角色空、应用权限抽屉、配置成员、树节点更多弹窗、模型 Tab 空态（租户未收到 / 应用未下发模型） |
| 项目对接指南 | 静态说明、复制失败；无应用工作台菜单权限时入口不可见 |
| 用户 / 组织 / 平台角色 | 无结果、已禁用、越权、冲突 409 |
| 应用登录品牌 | 草稿、已发布、发布失败 |
| 审计 / 鉴权模拟 | 无记录、无权限、查询失败 |
| 模型治理 / 模型用量 | 空目录、空账本、读取失败（不得伪装成成功空态）、待核对、下发关系计数与回收确认 |
| 个人信息页 | 加载中、读取失败（含重试）、无角色空态 |

窄屏管理导航必须让主要入口可发现；宽表横向滚动留在表格内，不得撑出整页。

## 8. 数据模型要点

```text
User（全局身份）
 └── TenantMembership
      ├── Organization / Group
      └── RoleBinding → Role → PermissionGrant / ResourceGrant / RoleDataScope

Tenant
 ├── Application（OIDC Client + 登录品牌 + 资源树）
 └── 组织 / 用户组 / 邀请

ModelCatalog（平台模型目录，超管维护）
 ├── ModelTenantGrant（平台 → 租户下发，status）
 └── ModelApplicationGrant（租户 → 应用下发，status）
      └── ModelUsageEvent / ModelUsageReservation（用量账本，按 tenant + application 归属）
```

核心表须含 `tenant_id` 或明确租户归属。所有授权查询从已验证身份上下文取租户，不信任请求体中的租户标识。接口契约以 OpenAPI 与 [应用对接](应用对接.md) 为准。

## 9. 管理台 UI 硬规则

适用于 `frontend/`（Vue 3 + Ant Design Vue + Tailwind）。气质：B2B IAM 控制台 — 冷静、可信、密而不挤、少装饰。

### 9.1 工程约定

- 有通用组件先用，禁止重复造轮子。
- 模块采用 `文件夹/index` 写法；有关联关系的文件放同一文件夹。
- 新列表页套页头 + 筛选 + 主卡片表格；禁止业务页自建第二套侧栏。
- 禁止在业务文件新增裸 hex；品牌色只改 token 一处。
- 间距为 4 的倍数。`shared/theme.ts`（现 `styles/theme`）只服务 OIDC 登录主题，不承担管理台色板。

### 9.2 气质与布局

- 管理台：深色侧栏 + 浅色内容区；侧栏选中为中性底 + 指示条，不要大面积炫光或彩虹渐变。
- 用户可选内容区暗色；侧栏始终深色中性。
- 登录 / OIDC 品牌页允许稍强品牌表现，禁止第三套主色。
- 中性色主导，品牌色作点缀。表格与筛选是一等公民，不为「好看」牺牲扫描效率。
- 每页主按钮最多一个；危险操作必须确认。
- 表格：空态 / loading / 操作列收敛；超宽用表内滚动。
- 表单标签完整、校验文案具体、提交中防重复。
- Modal / Drawer 关闭后重置状态。

### 9.3 改版验收要点

- 无新增裸 hex；主色占用克制。
- 新页复用通用组件与页面模板。
- 权限裁剪后的菜单无空白无权限项。
- 桌面与窄屏都要核对：入口可发现、无页级横向溢出。

## 10. 非功能需求

- 密码强哈希；登录失败节流可配置；管理接口与业务授权接口均服务端鉴权。
- 令牌、验证码、密钥不得进入普通应用日志。
- 采用 HTTPS 部署；敏感配置加密保存。
- 授权变更可追溯，并使相关会话或授权缓存失效。
- 管理后台适配主流桌面浏览器；登录页适配桌面与移动端。
- 首期模块化单体；PostgreSQL 为主库。

## 11. 验收标准

1. 超管 / 租户级可创建租户和应用，并登记合法回调；未登记回调无法获得授权码或令牌。
2. 三管理员模板按授权范围生效：超管全域可见；租户级只见自己租户的数据；应用级只见自己绑定的应用的数据；范围与节点都**只能向下**，下级看不见也配不了上级节点与角色。
3. 应用角色只在应用工作台配置；「应用权限」含资源权限与数据权限；「配置成员」可绑定成员。
4. 未授权用户无法通过直接调用后端接口执行受限操作；停用用户不能新登录或刷新令牌。
5. 同一全局用户加入多个租户后角色互不继承。
6. 每个应用可独立配置登录品牌；管理台外观变更不影响登录页。
7. 登录、用户状态、角色、应用和主题变更可查审计。
8. 浏览器端不包含客户端密钥、模型密钥或服务端长期凭证。
9. 业务权限既无数据权限叶子、也无 RoleDataScope 时在线 check 拒绝；映射数据码后放行。
10. 公开注册与配额 enforcement 保持关闭，除非产品与运维门槛全部满足并获明确授权。
11. 平台角色配置 = 「菜单→按钮」单树（菜单按钮自由勾选）+ 授权范围下拉（超管/租户级/应用级，只能选 ≤ 操作者范围）；「权限编码」页与 27 接口码目录已下线；后端接口按菜单/按钮节点判权，数据列表按授权范围过滤。
12. 创建用户必须至少绑定一个租户（表单默认选中一个），可选多选绑定组织与应用；绑应用自动补 `app.member`。
13. 用户管理「租户成员关系」支持直加租户（多选未加入的活动租户，disabled / departed 关系直接恢复）、逐行删除成员关系（移除记录与该租户授权并撤销该租户应用会话，不能删自己）；离职成员可「重新加入」，不再强制重走邀请。
14. 任意登录用户（含 L4 / 无管理码）可经顶栏用户菜单进入个人信息页，查看本人账号字段、有效角色与授权范围摘要；除展示名自助编辑（`PATCH /auth/me`，写审计含新旧值，空白双重拦截）外页面只读；不要求管理码、不进侧栏；数据仅取 `/auth/me` 契约；读取失败有重试，不伪装空态；窄屏顶栏用户区收敛为头像图标不溢出。
15. 模型三级分发：超管维护平台目录并下发租户；租户管理员仅能在本租户收到的模型范围内向应用下发 / 回收；`my-models` 只返回三级交集，回收或平台停用后立即不可见；下发与回收可查审计。
