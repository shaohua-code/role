# 统一身份与权限管理平台产品需求

本地启动见 [项目启动](项目启动.md)，部署门禁见 [部署与运维](部署与运维.md)，业务接入契约见 [应用对接](应用对接.md)。历史改动见根目录 [CHANGELOG.md](../CHANGELOG.md)。

**本阶段范围：** 只维护 IAM 管理台与绿场后端；**不做**业务项目接入联调，**不做** DeerFlow。公开注册与模型配额 enforcement 默认关闭。

## 1. 产品概述

### 1.1 定位

统一身份与权限管理平台（IAM）由统一登录中心和管理后台组成。平台统一管理身份、应用、组织、角色、权限策略、登录主题和审计；业务系统在自己的服务端执行授权结果，并负责本系统的业务数据访问控制。

### 1.2 目标

- 用户用一个账号登录多个已授权业务系统。
- 管理员在统一后台管理租户、应用、用户、组织、角色和权限。
- 每个接入应用可配置独立登录页主题。
- 业务系统基于统一身份和授权规则控制功能、数据与模型访问。
- 登录、授权变更及管理操作可查询、可审计。

### 1.3 设计原则

1. **认证集中，业务授权落地：** 平台提供可信身份和授权策略，业务服务端负责执行。
2. **默认拒绝：** 未明确授权的应用、接口、数据和模型调用均拒绝。
3. **租户隔离：** 租户是数据隔离边界，不能依赖前端传入的租户标识保障安全。
4. **最小权限：** 角色仅获得完成工作所需权限。
5. **看得见才能配：** 目录不出现操作者没有的权限，也配不进去。
6. **可扩展接入：** 采用标准认证协议和稳定的权限编码，避免绑定单一业务项目。

## 2. 范围

### 2.1 本期包含

- 用户登录、登出、密码重置；公开注册默认关闭。
- 租户、应用、用户、组织、用户组、成员邀请。
- OIDC 授权码登录；回调地址白名单；每应用登录品牌。
- 管理台浅色 / 深色 / 跟随系统、品牌主色、密度、可折叠侧栏。
- 五级平台角色 + 应用角色；27 个管理面权限码；应用业务码强制 data_scope。
- 应用资源树（菜单 / 按钮 / 数据规则）与权限编码并存。
- 登录日志及后台关键操作审计；鉴权模拟。
- 模型目录与用量账本（配额拦截默认关闭）。

### 2.2 本期不做

- 将业务数据（简历、知识库、工作流等）集中存入 IAM。
- 完整模型代理网关、供应商账单结算。
- 允许管理员上传任意 HTML / JavaScript / CSS 并在登录页执行。
- 把认证、授权、审计拆成多个独立微服务。
- DeerFlow / 其他业务项目接入联调；管理台「新项目接入」向导。
- MFA、企业 SSO、目录同步、公开注册上线、配额 enforcement 上线。

## 3. 角色与权限

### 3.1 两套目录、两类角色

平台管平台，应用管应用。**不要**按库表 `roles.kind`（platform / tenant / application）理解成三类产品角色。

| | 平台权限 | 应用权限 |
|---|---|---|
| 管什么 | IAM 管理台：租户、组织、用户、邀请、平台角色、审计、主题、模型账本 | 某个业务应用：业务码、菜单、按钮、数据规则 |
| 挂在哪 | 高级管理 → 权限编码 | 应用工作台：权限编码 / 资源树 |
| 挂给谁 | 只挂给平台角色 | 挂给该应用的应用角色 |
| 禁止 | 把业务码登记进平台目录或挂给平台角色 | 挂外应用业务码；挂操作者看不见的管理码 |

| | 平台角色 | 应用角色 |
|---|---|---|
| 有哪些 | 五个系统模板 + 未钉应用的自定义平台角色 | 钉住应用且 key 不在五模板里的自定义角色（如财务、只读） |
| 挂什么 | 只挂平台管理面码 | 本应用业务码 / 菜单 / 按钮，以及操作者看得见的租户 / 应用管理码 |
| 出现在哪 | 高级管理 → 平台角色 | 应用工作台 → 角色 |

同一人可同时持有平台角色和应用角色；生效权限按角色并集，互不串租户、互不串应用。

### 3.2 五级平台模板

层级：L1 `platform.admin` > L3 `tenant.admin` > 多应用 `apps.admin` ≥ 应用 `app.admin` > 应用角色 > 应用成员 `app.member`。

| 模板 key | 名称 | 管理码 | 能做什么 |
|---|---|---|---|
| `platform.admin` | 平台超级管理员 | 全部 27 码 | 全平台；建删租户；任命租户管理员 |
| `tenant.admin` | 租户管理员 | 模板 20 码 | 本租户全部应用；建删本租户应用；任命 `apps.admin` / `app.admin` |
| `apps.admin` | 多应用管理员 | 模板 16 码 | 与 `app.admin` 同结构，钉住单应用（管 N 个 = 绑 N 次）；可再任命该应用的 `app.admin`；不能建删应用 |
| `app.admin` | 应用管理员 | 模板 15 码 | 仅该应用；维护成员与应用角色；不能再任命应用管理员 |
| `app.member` | 应用成员 | 零管理码 | 平台侧只表示属于该应用；菜单 / 按钮由另行绑定的应用角色决定 |

边界：

- `GET /admin/permissions` 只出 `surface=management`；业务码只走应用工作台。
- 平台角色拒挂业务码。
- **看得见才能配：** 前四级管理员可新建角色，勾选自己已有 ∩ 范围内的码；看不见的码不出现、也不能勾选。四个管理员可改本级及以下预置模板，不能改上级、不能挂上级码。
- 给平台成员分配应用角色时，若还没有该应用的 `app.member`，同一事务自动补绑。
- 创建 / 删除应用仍仅 L1 / L3。`app.member` 不能配权、不能新建角色。
- 没有独立「审计人员」角色；审计接口挂在具备 `ops.audit.read` 的管理角色上。

前端 capabilities：租户域码在 `tenants[].codes`，应用码在 `tenants[].applications[].codes`。

### 3.4 三层配权

| 层 | 名称 | 一句话 | 用在哪 |
|---|---|---|---|
| ① | 权限编码 | 平台 / 管理能力码，以及应用业务码 | 管理台菜单 / 按钮裁剪；角色可挂这些码 |
| ② | 角色挂码 + 用户配角色 | 用户可多角色；生效 = 并集 | 谁能管什么 / 业务身份是谁 |
| ③ | 应用资源树 | 按应用的菜单 / 按钮 / 数据规则树 | 业务端 `my-resources` 渲染导航与按钮 |

防改错：

- **码管菜单：** 权限编码 → 管理台 capabilities。
- **角色管接口：** 用户角色并集 → API 能不能调。
- **资源树管业务端 UI：** 不替代接口鉴权。
- 行级数据范围靠 `data_scope` / 角色策略；资源树里的 `data_rule` 是挂载点，不替代行级强制。
- 「资源」不是「权限编码的别名」。旧说法「不建 Resource」已作废。

### 3.5 日常怎么配

1. **平台编码**在高级管理 → 权限编码（登记 / 启停仍仅 L1）。**应用业务码**在应用工作台「权限编码」Tab 登记。
2. **平台角色挂码**在高级管理 → 平台角色。**应用角色**在应用工作台 → 角色行「应用权限」：资源权限（挂码 + 资源树）与数据权限同一抽屉。
3. **配置成员**在角色行打开；「增加成员」从本租户成员多选绑定，自动补 `app.member`。给用户多选角色也可走用户管理。

排障顺序：用户有没有角色 → 角色有没有码 → 租户 / 应用上下文是否对。

### 3.6 数据范围

V1 支持 `tenant`、`self`、`organization`、`organization_tree`、`selected_organizations`。同一用户多个匹配角色的策略取并集；租户级范围覆盖其他子句。本人条件必须同时匹配全局 `owner_user_id` 与 `tenant_id`；组织条件匹配 `organization_id` 并且必须 AND `tenant_id`。

业务权限码必须配置 RoleDataScope，缺策略默认拒绝。`POST /authorization/check` 返回的 `any_of` 只是可信过滤条件，业务服务须编译进自己的 SQL / 检索，IAM 不直接读业务记录。前端隐藏菜单不能替代后端鉴权。

## 4. 信息架构

### 4.1 管理台侧栏

1. 运营总览（L1 `/overview`）
2. **应用工作台 / 组织工作台**（日常主入口）
3. 用户管理、成员邀请
4. **高级管理**（默认折叠）：平台角色、权限编码、用户组
5. 平台治理：租户、登录主题、模型治理 / 模型用量
6. 审计验证：审计日志、鉴权模拟

应用工作台：左树顶部「新建应用」；租户 / 应用节点右侧「⋯」也可新建，其余为编辑 / 密钥 / 受信 / 启停 / 删除。选中后右 Tab 为角色 / 权限编码 / 资源。角色行操作「应用权限」「配置成员」。
组织工作台：左树顶部「新建组织」；租户 / 组织节点右侧「⋯」也可新建下级，其余为负责人 / 启停 / 删除。选中后右 Tab 为成员 / 用户组。

**已下线：** 「新项目接入」（`/project-integration` → 应用工作台）；「应用角色与成员」（`/application-roles` → 应用工作台）；「应用管理」（`/applications` → 应用工作台）；「组织管理」（`/organizations` → 组织工作台）。

### 4.2 统一登录中心

登录、注册（默认关闭）、忘记密码、邮箱验证（短信通道暂不建设）、授权确认、错误 / 锁定 / 服务异常提示。

## 5. 核心流程

### 5.1 新应用（管理台侧）

1. L1 / L3 创建应用，填写标识、名称、至少一个登录回调。
2. 配置登出地址与来源域名白名单。
3. 配置 Logo 与登录主题并发布。
4. 系统自动放置 `app.admin` / `app.member`；在工作台登记业务码、资源树与应用角色。
5. 为业务权限配置 data_scope，给成员绑角色。
6. 业务系统按 [应用对接](应用对接.md) 接入 OIDC 与 check。

### 5.2 登录

1. 用户从业务系统发起登录，跳转统一登录中心。
2. 登录中心按应用加载已发布主题，校验凭据与账号状态。
3. 检查用户是否具有该应用访问权限。
4. 返回授权码至已登记回调；业务服务端换令牌并校验签名、签发方、受众和有效期。
5. 业务系统建立自己的会话，后续权限在服务端执行。

### 5.3 登录主题发布

选择应用 → 改 Logo / 背景 / 颜色 / 布局 / 文案 → 桌面与移动预览 → 保存草稿并发布。`show_register` 只控制视觉，不能开通注册。

## 6. 功能需求

### 6.1 用户与账号

- 全局身份：`active | disabled | locked`。登录、管理 API 和 OIDC 均只允许 `active`。不得把「离职」作为全局状态。
- 租户成员：`active | disabled | departed`。`disabled` 可恢复并保留角色；`departed` 清角色 / 组 / 组织，重新加入必须再邀请。
- 全局停用 / 锁定递增 `auth_version`、撤销 refresh session、消费未兑换 code / consent，同事务审计。管理员不能操作自己。
- 用户标识全局唯一；邮箱按验证状态管理；手机号字段保留但暂不建设短信通道。
- 密码不得明文或可逆保存。会话列表不展示设备名 / UA / IP；未申请 `offline_access` 的短 token 不能按会话 API 撤销。
- 公开注册默认关闭。若将来开放：须邮箱 OTP 两屏、独立注册密钥、consumer 租户、普通默认角色、政策链接与 SMTP；客户端不得提交 tenant / role / 管理员标志。新账号不因通过身份验证就取得跨组织数据。

### 6.2 租户、应用、组织

- 租户：创建、启停；停用后拒绝该租户新登录和令牌刷新。删除采用停用或归档，避免误删审计。
- 应用：至少一个登录回调、最多 20 个；HTTPS 或 localhost HTTP；创建后租户、Client ID、回调白名单只读。密钥明文只展示一次。停用后新的登录授权必须失败。创建 / 删除仅 L1 / L3；L2 只能改钉住的应用。
- 组织：租户内部门树；删除前检查成员及下级。用户组可继承角色。

### 6.3 应用、密钥与主题

- 回调必须与白名单精确匹配，不允许通配。
- 客户端密钥仅用于服务端，不得发给浏览器。
- 管理台外观与应用登录品牌分开：管理台用 ConfigProvider + CSS 变量，不接受任意 CSS / HTML / JS。登录主题图片限制格式与大小，数据库只存元数据和地址。

### 6.4 模型用量

- 管理台维护模型目录与用量视图；凭证不回读。
- 受信网关用 `IAM_MODEL_USAGE_API_KEY`（至少 32 字符）上报；不存 Prompt 或模型响应正文。
- `MODEL_QUOTA_ENFORCEMENT_ENABLED` 默认 false。预留到期后进入人工核对队列，不自动收费或释放。
- 费用按目录单价估算，未维护价格记为未知；当前无币种字段、无失败原因字段。

### 6.5 审计

记录登录成败、登出、密码重置、账号锁定、用户 / 应用 / 角色 / 主题 / 模型相关变更。不记录密码、完整令牌、客户端密钥或模型密钥明文。只提供查询，不提供修改和删除。

## 7. 页面关键状态

| 页面 | 关键状态 |
|---|---|
| 登录页 | 加载中、输入错误、账号锁定、服务异常、数据库待迁移 |
| 运营总览 | 空数据、加载失败、无查看权限 |
| 应用工作台 | 未选应用、角色空、应用权限抽屉、配置成员、树节点更多弹窗 |
| 用户 / 组织 / 平台角色 | 无结果、已禁用、越权、冲突 409 |
| 应用登录品牌 | 草稿、已发布、发布失败 |
| 审计 / 鉴权模拟 | 无记录、无权限、查询失败 |
| 模型用量 | 空账本、读取失败（不得伪装成成功空态）、待核对 |

窄屏管理导航必须让主要入口可发现；宽表横向滚动留在表格内，不得撑出整页。

## 8. 数据模型要点

```text
User（全局身份）
 └── TenantMembership
      ├── Organization / Group
      └── RoleBinding → Role → PermissionGrant / ResourceGrant / RoleDataScope

Tenant
 ├── Application（OIDC Client + 登录品牌 + 资源树）
 └── 组织 / 用户组 / 邀请
```

核心表须含 `tenant_id` 或明确租户归属。所有授权查询从已验证身份上下文取租户，不信任请求体中的租户标识。接口契约以 OpenAPI 与 [应用对接](应用对接.md) 为准。

## 9. 管理台 UI 硬规则

适用于 `frontend/`（Vue 3 + Ant Design Vue + Tailwind）。气质：B2B IAM 控制台 — 冷静、可信、密而不挤、少装饰。

### 9.1 工程约定

- 有通用组件先用，禁止重复造轮子。
- 模块采用 `文件夹/index` 写法；有关联关系的文件放同一文件夹。
- 新列表页套页头 + 筛选 + 主卡片表格；禁止业务页自建第二套侧栏。
- 禁止在业务文件新增裸 hex；品牌色只改 token 一处。
- 间距为 4 的倍数。`shared/theme.ts`（现 `styles/theme`）只服务 OIDC 登录主题，不承担管理台色板。

### 9.2 气质与布局

- 管理台：深色侧栏 + 浅色内容区；侧栏选中为中性底 + 指示条，不要大面积炫光或彩虹渐变。
- 用户可选内容区暗色；侧栏始终深色中性。
- 登录 / OIDC 品牌页允许稍强品牌表现，禁止第三套主色。
- 中性色主导，品牌色作点缀。表格与筛选是一等公民，不为「好看」牺牲扫描效率。
- 每页主按钮最多一个；危险操作必须确认。
- 表格：空态 / loading / 操作列收敛；超宽用表内滚动。
- 表单标签完整、校验文案具体、提交中防重复。
- Modal / Drawer 关闭后重置状态。

### 9.3 改版验收要点

- 无新增裸 hex；主色占用克制。
- 新页复用通用组件与页面模板。
- 权限裁剪后的菜单无空白无权限项。
- 桌面与窄屏都要核对：入口可发现、无页级横向溢出。

## 10. 非功能需求

- 密码强哈希；登录失败节流可配置；管理接口与业务授权接口均服务端鉴权。
- 令牌、验证码、密钥不得进入普通应用日志。
- 采用 HTTPS 部署；敏感配置加密保存。
- 授权变更可追溯，并使相关会话或授权缓存失效。
- 管理后台适配主流桌面浏览器；登录页适配桌面与移动端。
- 首期模块化单体；PostgreSQL 为主库。

## 11. 验收标准

1. L1 / L3 可创建租户和应用，并登记合法回调；未登记回调无法获得授权码或令牌。
2. 五级平台角色与两类目录按本文生效；下级看不见也配不了上级码。
3. 应用角色只在应用工作台配置；「应用权限」含资源权限与数据权限；「配置成员」可绑定成员。
4. 未授权用户无法通过直接调用后端接口执行受限操作；停用用户不能新登录或刷新令牌。
5. 同一全局用户加入多个租户后角色互不继承。
6. 每个应用可独立配置登录品牌；管理台外观变更不影响登录页。
7. 登录、用户状态、角色、应用和主题变更可查审计。
8. 浏览器端不包含客户端密钥、模型密钥或服务端长期凭证。
9. 业务权限缺 data_scope 时在线 check 拒绝。
10. 公开注册与配额 enforcement 保持关闭，除非产品与运维门槛全部满足并获明确授权。
