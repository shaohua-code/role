## 1. 三层各管什么

| 层 | 名称 | 一句话 | 主要用在哪 |
|---|---|---|---|
| ① | **权限编码** | 平台/管理能力码目录（如五域码） | 管理台菜单/按钮裁剪；角色可挂这些码 |
| ② | **角色挂码 + 用户配角色** | 用户可多角色；生效 = 角色并集 | 「谁能管什么 / 业务身份是谁」 |
| ③ | **应用资源树** | 按应用的菜单 / 按钮 / 数据规则树；角色勾选子集 | 业务端渲染菜单、显隐按钮；`my-resources` |

**不要混淆：**

- 「资源」≠「权限编码的别名」。蓝图里的资源 Tab = **第 ③ 层应用资源树**。
- 第 ① 层仍要维护（管理台自身能力）；第 ③ 层管业务应用的菜单结构。
- 行级数据范围仍主要靠 **data_scope / 角色策略**；资源树里的 `data_rule` 是挂载点，不要指望单靠它替代全部行级策略。

## 1.1 一句话防改错（必读）

- **码管菜单**：权限编码 → 管理台菜单/按钮显隐（capabilities）。
- **角色管接口**：用户角色并集 → API 能不能调。
- **资源树管业务端 UI**：应用资源树 → `my-resources` 渲染，**不**替代接口鉴权。
- 改菜单却改角色、或改接口却只改资源树，是最常见配错。

## 2. 日常怎么配（推荐顺序）

### A. 管理台能力（权限编码三步）

1. **权限编码**：在权限目录登记/确认需要的 code（英文码保留）。  
2. **角色挂码**：打开角色，把需要的权限编码挂上。  
3. **用户配角色**：用户管理里多选角色（并集生效）。

排障也按这个顺序：用户有没有角色 → 角色有没有码 → 租户/应用上下文是否对。

### B. 业务应用菜单 / 按钮（资源树）

1. 打开 **应用工作台**，左侧选应用。  
2. 进 **资源（应用资源树）** Tab：维护菜单树；按钮 / 数据规则挂在菜单下。  
3. 在 **角色** Tab（或角色资源授权）勾选该角色可见的资源节点。  
4. 用户持有该角色后，业务前端用 token 调 `GET /api/v1/authorization/my-resources?client_id=...` 拿嵌套树渲染。

资源类型约定：`menu` | `button` | `data_rule`。菜单可带 `path` / `icon` / `extra`；按钮与数据规则须挂在菜单下。
