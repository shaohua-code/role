## 1. 三层各管什么

| 层 | 名称 | 一句话 | 主要用在哪 |
|---|---|---|---|
| ① | **权限编码** | 平台/管理能力码目录（如五域码） | 管理台菜单/按钮裁剪；角色可挂这些码 |
| ② | **角色挂码 + 用户配角色** | 用户可多角色；生效 = 角色并集 | 「谁能管什么 / 业务身份是谁」 |
| ③ | **应用资源树** | 按应用的菜单 / 按钮 / 数据规则树；角色勾选子集 | 业务端渲染菜单、显隐按钮；`my-resources` |

**不要混淆：**

- 「资源」≠「权限编码的别名」。蓝图里的资源 Tab = **第 ③ 层应用资源树**。
- 第 ① 层仍要维护（管理台自身能力）；第 ③ 层管业务应用的菜单结构。
- 行级数据范围仍主要靠 **data_scope / 角色策略**；资源树里的 `data_rule` 是挂载点，不要指望单靠它替代全部行级策略。

## 1.1 一句话防改错（必读）

- **码管菜单**：权限编码 → 管理台菜单/按钮显隐（capabilities）。
- **角色管接口**：用户角色并集 → API 能不能调。
- **资源树管业务端 UI**：应用资源树 → `my-resources` 渲染，**不**替代接口鉴权。
- 改菜单却改角色、或改接口却只改资源树，是最常见配错。

## 2. 日常怎么配（推荐顺序）

### A. 管理台能力（权限编码三步）

1. **平台编码**在**高级管理 → 权限编码**（只出管理面码；登记/启停仍仅 L1）。**应用业务码**在**应用工作台「权限编码」Tab** 登记（L2 / L3 / 多应用管理员可新建）。  
2. **平台角色挂码**：高级管理 → 平台角色（五级模板 + 自定义平台角色，只挂管理面码；超管全量，下级按可见集）。**应用角色挂码**：应用工作台 → 角色 →「应用权限」（权限编码 + 资源树；数据权限同一抽屉）。  
3. **用户配角色**：给租户成员分配应用角色时，会同时成为该应用的平台成员（`app.member`）；生效权限 = 角色并集。

排障也按这个顺序：用户有没有角色 → 角色有没有码 → 租户/应用上下文是否对。

### B. 业务应用菜单 / 按钮（资源树）

1. 打开 **应用工作台**，左侧选应用。  
2. 进 **资源（应用资源树）** Tab：维护菜单树；按钮 / 数据规则挂在菜单下。  
3. 在 **角色** 行打开「应用权限」→ 资源权限，勾选该角色可见的资源节点。  
4. 用户持有该角色后，业务前端用 token 调 `GET /api/v1/authorization/my-resources?client_id=...` 拿嵌套树渲染。

资源类型约定：`menu` | `button` | `data_rule`。菜单可带 `path` / `icon` / `extra`；按钮与数据规则须挂在菜单下。

## 4.1 五级平台角色与两类目录（P405）

层级：L1 `platform.admin` > L3 `tenant.admin` > 多应用管理员 `apps.admin` ≥ 应用管理员 `app.admin` > 应用角色 > 应用成员 `app.member`。

| 操作者 | 可见管理码 | 可见业务码 | 可见对象 |
|---|---|---|---|
| L1 | 27 码全量 | 全站（仅应用工作台） | 所有租户 / 应用 |
| L3 | ⊆ 模板 20 码（无 L1 专属） | 本租户应用命名空间（工作台） | 本租户全部应用；不可列其他租户 |
| 多应用 / 应用管理员 | ⊆ 各自模板码（16 / 15） | **钉住应用**命名空间（工作台） | 钉住应用的角色 / 用量；审计尽力量化到该应用目标 |

高级管理「权限编码」不再列出业务码。挂码时能看见就能勾；平台角色拒业务码。系统预置角色：四个管理员可改本级及以下模板，不能改上级、不能挂上级码。应用角色可挂操作者看得见的租户 / 应用管理码与本应用业务码。创建/删除应用仍仅 L1 / L3。
