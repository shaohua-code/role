## 2. 本地开发与故障排查

首次启动流程见[快速启动指南](快速启动指南.md)。

Docker CLI 解析到系统目录并拒绝访问时，定位实际 Docker Desktop CLI 并传 `-DockerPath`，不要假定安装目录：

```powershell
$iamDockerCli = Get-Command docker.exe -CommandType Application -All -ErrorAction SilentlyContinue |
  Where-Object { $_.Source -and (Test-Path -LiteralPath $_.Source -PathType Leaf) } |
  Select-Object -First 1
if (-not $iamDockerCli) {
  $iamDockerCli = Get-Process docker -ErrorAction SilentlyContinue |
    Where-Object { $_.Path -and (Test-Path -LiteralPath $_.Path -PathType Leaf) } |
    Select-Object -First 1
  if ($iamDockerCli) { $iamDockerCli = [pscustomobject]@{ Source = $iamDockerCli.Path } }
}
if (-not $iamDockerCli) { throw '未找到 Docker CLI，请先修复安装/PATH' }
& $iamDockerCli.Source compose version
.\start-local.ps1 -DockerPath $iamDockerCli.Source
```

要点：

- 日常停止只用 `down`，保留 `iam-postgres-data` 与 `iam-oidc-signing-data`；**禁止 `down -v`**（删除数据库及签名密钥卷）
- 开发环境挂载源码，API reload / Vite 热更新生效；开发 Compose 不用于生产
- 隔离验证 `.\verify-local.ps1 -DockerPath '<docker.exe>'`：只迁移并删除随机 `iam_test_<uuid>` 库，不升级开发主库；不代替真实登录/E2E

readiness 探测（只读，不自动迁移）：

```powershell
Invoke-WebRequest 'http://127.0.0.1:8002/api/v1/ready' -NoProxy -SkipHttpErrorCheck -TimeoutSec 5
docker compose exec -T api alembic current
docker compose exec -T api alembic heads
```

`health` 只证明 API 进程；`ready` 还校验 PostgreSQL 连接及 `alembic_version` 与全部 heads 相等。

| 症状 | 处理 |
|---|---|
| Docker daemon 不可用 | 启动 Docker Desktop，等 Engine Running，再核对 CLI/Compose |
| 登录页 502 | `compose ps`、三服务日志、直接 `/ready`；502 说明代理未取得 API 响应，不是密码错误 |
| `database_not_ready` | 核对 API `DATABASE_URL` 与数据库 role 密码一致；未确认前不 migrate/bootstrap |
| `password authentication failed for user "iam"` | 保留卷；环境变量不改既有 role 密码，重建 API 也无效，按受控凭据恢复流程一致化 |
| `database_migration_pending` | 只读比较 `current`/`heads`；按第 4 节备份授权后迁移，Console 可展示属预期 |
| ready 200 但 Console 502 | 确认访问 5175、Console 日志与 `.env` 端口，再 `up -d api console` |
| 账号/密码错误 | 用本机管理员凭据；引导变量不重置旧账号，禁止删库卷恢复 |

日志交付前脱敏：数据库口令、JWT/Client Secret、Cookie、token、私钥；不输出展开后的 Compose 配置或实际 `.env`。`pg_isready` 不验证 API 密码，应凭 API 凭据做只读 `SELECT 1`。

## 3. 备份与恢复演练

对应 A02。备份目标须受访问控制、加密、异机保存；脚本不加密、不异地、不自动调度。仓库忽略 `secure-backups/` 不代表目录受保护。

```powershell
# 只读预检，不生成归档
.\deploy\backup-postgres.ps1 -ValidateOnly -DockerPath '<docker.exe>'

# 开发备份
.\deploy\backup-postgres.ps1 `
  -OutputDirectory 'D:\secure-backups\iam-dev' `
  -DockerPath '<docker.exe>'

# 生产备份
.\deploy\backup-postgres.ps1 `
  -ComposeFile 'compose.production.yaml' `
  -EnvironmentFile '.env.production.local' `
  -PostgresService 'postgres' `
  -OutputDirectory 'D:\secure-backups\iam' `
  -DockerPath '<docker.exe>'
```

- 产出 custom-format dump + SHA-256 sidecar；公开参数 `ComposeFile`/`EnvironmentFile`/`PostgresService`/`OutputDirectory`/`DockerPath`/`ValidateOnly`，默认 `compose.yaml`/`.env`/`postgres`
- dump 不含 `.env`、roles/global、OIDC 私钥，分别保管；预检/归档可读 ≠ 可恢复
- 开发签名私钥确需副本时，复制到已受保护目录并按批准流程加密；不进聊天/工单/仓库

恢复演练（随机 `iam_restore_check_<UUID>` 库，不动业务库；用实际归档绝对路径）：

```powershell
.\deploy\verify-postgres-restore.ps1 `
  -BackupFile 'D:\secure-backups\iam-dev\iam-postgres-YYYYMMDDTHHMMSSZ-XXXXXXXX.dump' `
  -DockerPath '<docker.exe>'
```

- 默认校验 SHA-256 sidecar；`-KeepScratchDatabase` 成功后保留随机库，`-SkipChecksum` 仅限来源可信的旧备份；参数默认与备份相同
- 演练后核对 Alembic revision 与关键表；**真实归档恢复演练未运行**。完整恢复另需隔离 API 验证 readiness/登录/OIDC，禁止把业务 `DATABASE_URL` 指向演练库

## 5. 生产发布

对应 D04。`compose.production.yaml` 链路：PostgreSQL → one-shot migrate → API → Nginx Console → Caddy HTTPS；API/DB 不暴露宿主端口。要求 psycopg 3 URL、32+ 字符 JWT secret、管理员 allow-list、HTTPS issuer。基础镜像尚未锁 digest。

1. 复制 `.env.production.example` 为本机忽略的 `.env.production.local`，Secret Manager 填真实值；`IAM_RELEASE_TAG` 不可变；准备独立 PKCS#8 RSA 私钥（2048+ 位、只读挂载、UID 10001 可读）；确认 DNS A/AAAA、80/443、镜像/依赖源。
2. 构建与静态预检（不启动服务、不连库、不迁移）：

```powershell
docker compose -f compose.production.yaml --env-file .env.production.local build
.\deploy\validate-production.ps1 -EnvironmentFile '.env.production.local' -DockerPath '<docker.exe>'
```

3. 完成备份/演练/授权后一次性引导（依赖 migrate），成功后移除 `IAM_BOOTSTRAP_ADMIN_PASSWORD`，再按发布窗口启动：

```powershell
docker compose -f compose.production.yaml --env-file .env.production.local --profile bootstrap run --rm bootstrap-admin
docker compose -f compose.production.yaml --env-file .env.production.local up -d caddy
```

4. 验证 `https://<IAM_DOMAIN>/`、`/api/v1/ready`、`/.well-known/openid-configuration` 及真实登录/权限/管理写入，按[验收记录](验收记录.md)留证据。

每次升级同样先备份与兼容性审阅；`up -d caddy` 不是无数据库影响的普通启动。

## 6. TLS、来源地址与 RSA 轮换

- `TRUST_PROXY_CLIENT_IP=true` 只信任 Caddy 覆写、Nginx 传递的 `X-IAM-Client-IP`，未知/非法返回 503；CDN/LB 出口 CIDR 写入 `deploy/caddy/trusted-proxies/edge.caddy`，禁止信任 `private_ranges` 或浏览器转发头
- Nginx 设 CSP/防嵌入/MIME/Referrer 等安全头；修改缓存 location 后须生产镜像测试。各层日志不得落 code/token/state/password/secret/id_token_hint
- RS256 双 key 轮换（JWKS 按 `kid` 验签，RP 缓存以最长实际缓存为准）：
  1. 全实例部署双 key 支持（活动=旧 key、无备用）
  2. 预发布：活动=旧、备用=新，只改 Secret 引用后校验并重建 API；等全部 RP/JWKS 缓存刷新（新 token 仍用旧 kid）
  3. 原子切换：活动=新、备用=旧，协调全部 API 重建（多副本一次切换或蓝绿）
  4. 等最长 JWT 有效期与缓存退出后清除备用引用；确认 JWKS 仅活动 key 后按策略销毁旧私钥

```powershell
docker compose -f compose.production.yaml -f compose.production.key-rotation.yaml --env-file .env.production.local config --quiet
.\deploy\validate-production.ps1 -EnvironmentFile '.env.production.local' -IncludeKeyRotation -DockerPath '<docker.exe>'
docker compose -f compose.production.yaml -f compose.production.key-rotation.yaml --env-file .env.production.local up -d --force-recreate api
```

- 重叠期回退：恢复旧活动/新备用并协调全部实例；旧 key 退出 JWKS/缓存后须重新预发布

## 7. 账户、会话与邮件

- 全局停用/锁定：递增 `auth_version`、撤销 refresh session、消费未兑换 code/consent、同事务审计；管理员不能操作自己。单 tenant 停用仅撤该 tenant 凭据；离职保留 membership 历史、清角色/组，不算全局状态
- 会话目录仅返回 ID/client/时间；撤销管理 session 在线拒绝，OIDC 撤销整个 family；未申请 `offline_access` 的短 token 无持久 session，不能按会话 API 撤销
- 业务侧离线验签看不到即时撤权（OIDC access token 默认 10 分钟）；敏感请求须在线授权/Introspection。DeerFlow `/auth/logout` 只清本地 session/vault
- 凭据清理：默认 3600 秒间隔、每类 1000 行（`IAM_CREDENTIAL_CLEANUP_*`）；不删 refresh family、邀请、审计、usage reservation
- 登录节流：900 秒内同账号/来源 8 次、同来源 60 次失败后阻止 900 秒（`IAM_LOGIN_*`）；HMAC 基于 JWT secret
- SMTP：STARTTLS/SSL 二选一，secret 只入 API（不给 migrate/bootstrap）；未配置返回服务不可用。邀请默认手动交付，验收后开 `IAM_INVITATION_EMAIL_ENABLED=true`
- 公开注册保持关闭（`IAM_ALLOW_PUBLIC_REGISTRATION=false`）；开放前 D02 门槛全部通过：双开关、consumer tenant/默认角色、HTTPS 政策链接、独立 32+ 字符 `IAM_PUBLIC_REGISTRATION_SECRET`、两屏 OTP、WAF/邮件配额告警、可计费权益保护等；隔离测试不是生产依据

## 8. 模型核对与剩余缺口

- 预留始终持久化；Provider 可能完成但 outbox 未提交的调用 10 分钟后进入人工核对队列，不自动收费/释放，仅凭证据确认未调用才释放
- 管理 API：`GET /api/v1/admin/model-usage/reviews`（limit 1–200 默认 50）、`GET /api/v1/admin/model-usage/events`（默认 100）；`{items,total,limit,offset}`，409 按并发已处理重载
- 配额 enforcement 保持 `false`，真实闭环（C02）验收前不开启；租户 RPM/TPM 不代替每用户成本权益
- 待建设/验收：自动备份调度、加密/异地、保留清理、key 轮换、告警、容量/HA、RPO/RTO 演练；本文不创建后台任务

## 9. 部署输入清单

P0（目标环境验收）：

| 输入 | 要求 |
|---|---|
| 目标环境/数据库 | IAM 与 DeerFlow 服务/库/revision、受保护备份目录与负责人、维护窗口、明确迁移授权；IAM 与 Harness/扩展链不混用 |
| IAM/OIDC | issuer/API base、tenant/application UUID、provider ID、Client ID、精确 callback/logout URL、scopes（默认 `openid profile email`，长会话加 `offline_access`） |
| 角色与权限 | permission/resource/action、角色 grant、owner/self data_scope；迁移只登记目录不 grant |
| 模型与工具 | 实际 `models[].name` → 活动 model UUID、`model.invoke` grant；工具默认逐 `resource_id=tool_name` 授权；写响应需对应 read 权限，完整矩阵见[技术架构与接入](技术架构与接入.md)。PAT 不能代替 vault 联调 |
| 存量身份 | `(issuer, sub)` → `user_id` 映射与冲突方案；邮箱不作静默合并键，不批量降级 |
| 业务范围 | 首阶段 owner-only，tenant/org scope 拒绝；无有效 vault session 即暂停定时任务 |
| 公开注册（如启用） | consumer tenant/角色、政策链接、SMTP/发件域、注册 secret、WAF/配额、成本权益 |

P1（生产）：Linux Docker 主机与 `IAM_DOMAIN` DNS、不可变 `IAM_RELEASE_TAG`、CDN/LB 出口 CIDR、`IAM_POSTGRES_PASSWORD`/`IAM_JWT_SECRET`（32+）、RSA key（2048+ PKCS#8，UID 10001 可读）、`IAM_BOOTSTRAP_ADMIN_PASSWORD`（一次性）、DeerFlow vault key（`DEERFLOW_IAM_TOKEN_ENCRYPTION_KEY`，丢失须重加密/重登录）、SMTP、备份/RPO/RTO 目标。

P2（运营）：每模型 `reserved_output_tokens` 与核对责任人、网关 `IAM_MODEL_USAGE_API_KEY` 保管轮换、账本/审计留存年限、登录主题素材、MFA/导出/注销等账户能力。角色复制规则已定：默认不复制权限，可单次复制活动权限/资源授权/范围，不复制用户组绑定。
