# 部署与运维

本地最短路径见 [项目启动](项目启动.md)。产品规则见 [产品需求](产品需求.md)。历史事实见 [CHANGELOG.md](../CHANGELOG.md)。

**门禁：** 数据库迁移须先受保护备份、审阅影响并取得明确授权。开发 Compose 普通启动不迁移、不 bootstrap。生产 `up` 的依赖链含 one-shot migrate，属发布流程，不得借普通启动绕过门禁。公开注册与配额 enforcement 保持关闭。整理文档不授权数据库写入。

## 1. 本地开发与故障排查

首次启动见 [项目启动](项目启动.md)。Docker CLI 被 Windows 别名遮蔽时，定位实际 Docker Desktop CLI 并传 `-DockerPath`：

```powershell
$iamDockerCli = Get-Command docker.exe -CommandType Application -All -ErrorAction SilentlyContinue |
  Where-Object { $_.Source -and (Test-Path -LiteralPath $_.Source -PathType Leaf) } |
  Select-Object -First 1
if (-not $iamDockerCli) {
  $iamDockerCli = Get-Process docker -ErrorAction SilentlyContinue |
    Where-Object { $_.Path -and (Test-Path -LiteralPath $_.Path -PathType Leaf) } |
    Select-Object -First 1
  if ($iamDockerCli) { $iamDockerCli = [pscustomobject]@{ Source = $iamDockerCli.Path } }
}
if (-not $iamDockerCli) { throw '未找到 Docker CLI，请先修复安装/PATH' }
& $iamDockerCli.Source compose version
.\start-local.ps1 -DockerPath $iamDockerCli.Source
```

要点：

- 日常停止只用 `down`，保留 `iam-postgres-data` 与 `iam-oidc-signing-data`；**禁止 `down -v`**（删除数据库及签名密钥卷）。
- 开发环境挂载源码，API reload / Vite 热更新生效；开发 Compose 不用于生产。
- 隔离验证 `.\verify-local.ps1 -DockerPath '<docker.exe>'`：只迁移并删除随机 `iam_test_<uuid>` 库，不升级开发主库；不代替真实登录。

readiness 探测（只读，不自动迁移）：

```powershell
Invoke-WebRequest 'http://127.0.0.1:8002/api/v1/ready' -NoProxy -SkipHttpErrorCheck -TimeoutSec 5
docker compose exec -T api alembic current
docker compose exec -T api alembic heads
```

`health` 只证明 API 进程；`ready` 还校验 PostgreSQL 连接及 `alembic_version` 与全部 heads 相等。

| 症状 | 处理 |
|---|---|
| Docker daemon 不可用 | 启动 Docker Desktop，等 Engine Running，再核对 CLI / Compose |
| 终端提示 Docker named pipe 或本机 socket `permission denied` | 只说明当前终端无权访问，不能判断服务是否停止。换到可执行 `docker compose` 的 PowerShell 做只读探测 |
| 登录页 502 | `compose ps`、三服务日志、直接 `/ready`；502 说明代理未取得 API 响应，不是密码错误 |
| `database_not_ready` | 核对 API `DATABASE_URL` 与数据库 role 密码一致；未确认前不 migrate / bootstrap |
| `password authentication failed for user "iam"` | 保留卷。`POSTGRES_PASSWORD` 只在卷首次初始化时生效，改 `.env` 或重建容器都不会改既有 role 密码。在 postgres 容器内以本地 trust 执行 `ALTER USER iam WITH PASSWORD` 对齐到当前 `.env`，再 `up -d api` |
| `database_migration_pending` | 只读比较 `current` / `heads`；按第 3 节备份授权后迁移 |
| ready 200 但 Console 502 | 确认访问 5175、Console 日志与 `.env` 端口，再 `up -d api console` |
| 账号 / 密码错误 | 用本机管理员凭据；引导变量不重置旧账号，禁止删库卷恢复 |

日志交付前脱敏：数据库口令、JWT / Client Secret、Cookie、token、私钥；不输出展开后的 Compose 配置或实际 `.env`。修改 `.env` 的 `IAM_POSTGRES_PASSWORD` 不会改变已初始化数据库的 role 密码。

## 2. 备份与恢复演练

备份目标须受访问控制、加密、异机保存；脚本不加密、不异地、不自动调度。仓库忽略 `secure-backups/` 不代表目录受保护。

```powershell
.\deploy\backup-postgres.ps1 -ValidateOnly -DockerPath '<docker.exe>'

.\deploy\backup-postgres.ps1 `
  -OutputDirectory 'D:\secure-backups\iam-dev' `
  -DockerPath '<docker.exe>'

.\deploy\backup-postgres.ps1 `
  -ComposeFile 'compose.production.yaml' `
  -EnvironmentFile '.env.production.local' `
  -PostgresService 'postgres' `
  -OutputDirectory 'D:\secure-backups\iam' `
  -DockerPath '<docker.exe>'
```

产出 custom-format dump + SHA-256 sidecar。dump 不含 `.env`、数据库 roles/global、OIDC 私钥，须分别保管。预检 / 归档可读 ≠ 可恢复。

恢复演练（随机 `iam_restore_check_<UUID>` 库，不动业务库）：

```powershell
.\deploy\verify-postgres-restore.ps1 `
  -BackupFile 'D:\secure-backups\iam-dev\iam-postgres-YYYYMMDDTHHMMSSZ-XXXXXXXX.dump' `
  -DockerPath '<docker.exe>'
```

默认校验 SHA-256 sidecar。演练后核对 Alembic revision 与关键表。完整恢复另需隔离 API 验证 readiness / 登录 / OIDC，禁止把业务 `DATABASE_URL` 指向演练库。开发签名私钥确需副本时，复制到已受保护目录并按批准流程加密；不进聊天 / 工单 / 仓库。

## 3. 迁移授权与回退

执行前记录：目标库与当前 revision、目标 head、代码 / 镜像标识、归档及恢复结果、负责人 / 窗口、**明确授权**。

已知影响（绿场链 `0001`–`0005`；以后每次迁移重新审阅源码）：

| Revision | 影响 |
|---|---|
| `0005_permission_kind` | `permissions.kind`（menu/button/api/data）+ 按编码回填；不删表、不改 27 个接口码字符串。种子后的新菜单/按钮行默认 `api`，需再按前缀回填 |
| `0004_owner_backchannel` | 应用 backchannel logout 字段 |
| `0003_resource_description` | 资源说明列 |
| `0002_application_resources` | 应用资源树 |
| `0001_greenfield_iam` | 绿场基线 |

已授权升级与复核：

```powershell
docker compose --profile migrate run --build --rm migrate
if ($LASTEXITCODE -ne 0) { throw '迁移失败，停止发布并保留诊断证据' }
docker compose up -d api console
docker compose exec -T api alembic current
docker compose exec -T api alembic heads
Invoke-WebRequest -UseBasicParsing 'http://localhost:8002/api/v1/ready'
```

确认 revision 与 head 一致、ready / Console 200，再按实际改动复跑隔离验证与真实登录。API / Console 重启本身不迁移。

回退：

- 不修改已应用 migration，不用 `alembic downgrade` 当通用回滚。
- 无法兼容时：dump 恢复到**新的空 PostgreSQL 目标**，核对 revision / 数据 / 可用性后切换连接。
- 同时从保管处恢复 OIDC key 与原 `JWT_SECRET`，否则旧 token 失效；保留 PostgreSQL 卷、签名资料与 Caddy `/data`。

## 4. 生产发布

`compose.production.yaml` 链路：PostgreSQL → one-shot migrate → API → Nginx Console → Caddy HTTPS；API / DB 不暴露宿主端口。要求 psycopg 3 URL、32+ 字符 JWT secret、管理员 allow-list、HTTPS issuer。

1. 复制 `.env.production.example` 为本机忽略的 `.env.production.local`，Secret Manager 填真实值；`IAM_RELEASE_TAG` 不可变；准备独立 PKCS#8 RSA 私钥（2048+ 位、只读挂载、UID 10001 可读）；确认 DNS、80 / 443、镜像源。
2. 构建与静态预检（不启动服务、不连库、不迁移）：

```powershell
docker compose -f compose.production.yaml --env-file .env.production.local build
.\deploy\validate-production.ps1 -EnvironmentFile '.env.production.local' -DockerPath '<docker.exe>'
```

3. 完成备份 / 演练 / 授权后一次性引导（依赖 migrate），成功后移除 `IAM_BOOTSTRAP_ADMIN_PASSWORD`，再按发布窗口启动：

```powershell
docker compose -f compose.production.yaml --env-file .env.production.local --profile bootstrap run --rm bootstrap-admin
docker compose -f compose.production.yaml --env-file .env.production.local up -d caddy
```

4. 验证 `https://<IAM_DOMAIN>/`、`/api/v1/ready`、`/.well-known/openid-configuration` 及真实登录 / 权限 / 管理写入。

每次升级同样先备份与兼容性审阅；`up -d caddy` 不是无数据库影响的普通启动。`ALLOW_BOOTSTRAP_EMAIL_BYPASS` 生产保持 false。

## 5. TLS、来源地址与 RSA 轮换

- `TRUST_PROXY_CLIENT_IP=true` 只信任 Caddy 覆写、Nginx 传递的 `X-IAM-Client-IP`，未知 / 非法返回 503；CDN / LB 出口 CIDR 写入 `deploy/caddy/trusted-proxies/edge.caddy`，禁止信任 `private_ranges` 或浏览器转发头。
- Nginx 设 CSP / 防嵌入 / MIME / Referrer 等安全头；修改缓存 location 后须生产镜像测试。各层日志不得落 code / token / state / password / secret / id_token_hint。
- RS256 双 key 轮换（JWKS 按 `kid` 验签）：
  1. 全实例部署双 key 支持（活动 = 旧 key、无备用）
  2. 预发布：活动 = 旧、备用 = 新，只改 Secret 引用后校验并重建 API；等全部 RP / JWKS 缓存刷新
  3. 原子切换：活动 = 新、备用 = 旧，协调全部 API 重建
  4. 等最长 JWT 有效期与缓存退出后清除备用引用；确认 JWKS 仅活动 key 后按策略销毁旧私钥

```powershell
docker compose -f compose.production.yaml -f compose.production.key-rotation.yaml --env-file .env.production.local config --quiet
.\deploy\validate-production.ps1 -EnvironmentFile '.env.production.local' -IncludeKeyRotation -DockerPath '<docker.exe>'
docker compose -f compose.production.yaml -f compose.production.key-rotation.yaml --env-file .env.production.local up -d --force-recreate api
```

重叠期回退：恢复旧活动 / 新备用并协调全部实例；旧 key 退出 JWKS / 缓存后须重新预发布。

## 6. 账户、会话与邮件

- 全局停用 / 锁定：递增 `auth_version`、撤销 refresh session、消费未兑换 code / consent、同事务审计；管理员不能操作自己。单 tenant 停用仅撤该 tenant 凭据。
- 会话目录仅返回 ID / client / 时间；撤销管理 session 在线拒绝，OIDC 撤销整个 family。
- 业务侧离线验签看不到即时撤权；敏感请求须在线授权 / Introspection。
- 凭据清理：默认 3600 秒间隔、每类 1000 行（`IAM_CREDENTIAL_CLEANUP_*`）；不删 refresh family、邀请、审计、usage reservation。
- 登录节流：900 秒内同账号 / 来源 8 次、同来源 60 次失败后阻止 900 秒（`IAM_LOGIN_*`）；HMAC 基于 JWT secret。
- SMTP：STARTTLS / SSL 二选一，secret 只入 API（不给 migrate / bootstrap）；未配置返回服务不可用。邀请默认手动交付，验收后开 `IAM_INVITATION_EMAIL_ENABLED=true`。163 使用 SMTP 授权码，不是登录密码。
- 公开注册保持 `IAM_ALLOW_PUBLIC_REGISTRATION=false`。开放前须满足产品需求中的注册门槛：双开关、consumer tenant / 默认角色、HTTPS 政策链接、独立 32+ 字符 `IAM_PUBLIC_REGISTRATION_SECRET`、两屏 OTP、WAF / 邮件配额告警。隔离测试不是生产依据。

## 7. 模型核对

- 预留始终持久化；Provider 可能完成但 outbox 未提交的调用 10 分钟后进入人工核对队列，不自动收费 / 释放，仅凭证据确认未调用才释放。
- 管理 API：`GET /api/v1/admin/model-usage/reviews`、`GET /api/v1/admin/model-usage/events`。
- 配额 enforcement 保持 `false`；租户 RPM / TPM 不代替每用户成本权益。
- 待建设：自动备份调度、加密 / 异地、保留清理、告警、容量 / HA、RPO / RTO 演练。本文不创建后台任务。

## 8. 部署输入清单

目标环境验收前准备（密钥不进文档或聊天）：

| 输入 | 要求 |
|---|---|
| 目标环境 / 数据库 | 服务 / 库 / revision、受保护备份目录与负责人、维护窗口、明确迁移授权 |
| IAM / OIDC | issuer / API base、tenant / application UUID、Client ID、精确 callback / logout URL、scopes（默认 `openid profile email`，长会话加 `offline_access`） |
| 角色与权限 | 权限码、角色 grant、owner / self data_scope；迁移只登记目录不 grant |
| 存量身份 | `(issuer, sub)` → `user_id` 映射与冲突方案；邮箱不作静默合并键 |
| 公开注册（如启用） | consumer tenant / 角色、政策链接、SMTP、注册 secret、WAF / 配额、成本权益 |

生产另需：Linux Docker 主机与 `IAM_DOMAIN` DNS、不可变 `IAM_RELEASE_TAG`、CDN / LB 出口 CIDR、`IAM_POSTGRES_PASSWORD` / `IAM_JWT_SECRET`（32+）、RSA key、一次性 `IAM_BOOTSTRAP_ADMIN_PASSWORD`、SMTP、备份 / RPO / RTO 目标。

Client Secret、数据库密码与私钥只由管理员写入后端 Secret Manager。
