## 2. 产品范围和已经确认的规则

- 平台统一身份、租户、应用、角色、权限、数据范围、审计与模型用量账目；业务系统自己保存业务数据，并在服务端执行 IAM 判定。当前唯一正式试点是 DeerFlow。AI Resume 和 Knowledge Base 的旧 IAM 接入已清理，不能计入现行交付。
- DeerFlow 首阶段的项目、线程、运行、文档和个人资源仅 owner 可访问。IAM `owner/self` 范围与业务库的本地 `user_id` 条件必须同时成立；没有可信业务归属字段的 tenant/organization sharing 拒绝。组织共享、旧数据回填和新迁移留给 F01 评审。
- OIDC 稳定身份以 `(issuer, sub)` 识别；DeerFlow 首登只创建普通用户。同邮箱不自动合并存量账号，更不能凭邮箱或浏览器标志提权。管理权限由显式 IAM grant 决定；共享配置另保留 DeerFlow 本地管理员门禁。
- DeerFlow `/auth/logout` 只清理本地 session/vault。已有 RFC 7009 客户端原语不代表本阶段要向 issuer 发送 token 或接线上游撤销。
- 无明确 grant、无有效 owner/self、身份/应用/租户不匹配、IAM 超时或响应异常均失败关闭。没有最后有效 session 的定时任务暂停并取消待启动工作，不暗中使用独立后台身份。
- 模型调用先按精确档案和资源 ID 授权，再预留、调用 Provider、持久化 outbox、幂等结算。Provider 可能已调用而 outbox 未提交时，预留保留进入管理员核对；10 分钟到期不自动收费或释放，仅确认 Provider 未调用才能释放。
- 公开注册受全局开关、应用 `open` 策略及 `consumer` 租户三重门禁约束，仍默认关闭；注册上线还需普通角色、政策版本、SMTP、反滥用和成本权益验收。模型 RPM/TPM 不能替代新用户权益。配额拦截仍关闭，源码和 mock 通过不构成开启依据。
- IAM 开发 Compose 普通启动不自动迁移或 bootstrap。生产启动有 one-shot migration，因此发布前须完成目标核对、受保护备份及恢复演练、影响审阅和该次发布/迁移授权。2026-10-14 的授权只覆盖当次开发库 0021→0031。

DeerFlow 当前 permission map 静态核对为 36 项。`model:use` 映射通用 `model.invoke`，按每个 IAM model UUID 授资源级权限；catalog 中的 `deerflow.model.use` 当前未引用。工具按服务端注册名授权，模型目录可见不等于可调用。迁移 `0026–0030` 仅登记权限码，没有给角色自动授予 grant。逐项映射及特殊路由见[技术架构与接入](技术架构与接入.md)第 5 节。

多项目“少量配置即可接入”是 F02 的后续目标：现有 SDK 可复用，FastAPI/Node 适配器、自动路由、持久会话适配、权限清单导入和最小 CRUD 示例尚未交付。其它正式项目须待 DeerFlow 试点验收后评审。
