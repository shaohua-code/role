# 快速启动指南

更新时间：**2026-10-14（Asia/Shanghai）**。面向 `D:\project\role` 本地开发环境的最短启动路径；备份、迁移门禁和生产发布见[部署与运维](部署与运维.md)，任务状态见[项目总览与进度](项目总览与进度.md)。

## 1. 前置检查

在 PowerShell 中进入 `D:\project\role`，确认 Docker Desktop 已启动、Engine Running、Compose v2 可用。先定位实际 CLI，后续命令复用这个路径，避免 Windows 的 `docker` 执行别名遮蔽 Docker Desktop：

```powershell
Set-Location -LiteralPath 'D:\project\role'
$iamDocker = Get-Command docker.exe -CommandType Application -All -ErrorAction SilentlyContinue |
  Where-Object { $_.Source -and (Test-Path -LiteralPath $_.Source -PathType Leaf) } |
  Select-Object -First 1 -ExpandProperty Source
if (-not $iamDocker) {
  $iamDocker = Get-Process docker -ErrorAction SilentlyContinue |
    Where-Object { $_.Path -and (Test-Path -LiteralPath $_.Path -PathType Leaf) } |
    Select-Object -First 1 -ExpandProperty Path
}
if (-not $iamDocker) { throw '未找到 Docker CLI，请先修复 Docker Desktop 或 PATH' }
& $iamDocker compose version
if ($LASTEXITCODE -ne 0) { throw 'Docker Compose v2 不可用' }
& $iamDocker info --format '{{.ServerVersion}}'
if ($LASTEXITCODE -ne 0) { throw 'Docker Engine 未就绪' }
```

上述命令也会从正在运行的 Docker 进程定位 CLI，本机当前安装位置未加入此终端的 PATH。若仍找不到 CLI 或无法连接 Engine，先处理 Docker Desktop；不要因 `docker` 别名异常而猜测安装目录。详情见[部署与运维](部署与运维.md)第 2 节。

## 2. 首次配置

仅当根目录没有 `.env` 时创建（禁止覆盖已有运行配置）：

```powershell
if (-not (Test-Path -LiteralPath '.env' -PathType Leaf)) {
  Copy-Item -LiteralPath '.env.compose.example' -Destination '.env'
}
notepad .env
```

- `IAM_JWT_SECRET` 和使用时的 `IAM_MODEL_USAGE_API_KEY` 至少 32 字符；管理员密码至少 16 字符；数据库密码用 URL-safe 随机串
- `.env` 不提交、不贴聊天

## 3. 启动

```powershell
.\start-local.ps1 -DockerPath $iamDocker
```

脚本会构建并启动 PostgreSQL/API/管理台；它不迁移、不创建管理员。

## 4. 就绪探测

```powershell
Invoke-WebRequest 'http://127.0.0.1:8002/api/v1/ready' -NoProxy -SkipHttpErrorCheck -TimeoutSec 5
& $iamDocker compose exec -T api alembic current
& $iamDocker compose exec -T api alembic heads
```

`health` 200 只证明 API 进程；`ready` 200 才可提交登录。若返回 503 `database_migration_pending`，先确认 `current` 落后于 `heads`，再按下节处理。若是数据库连接或凭据错误，先按[部署与运维](部署与运维.md)第 2 节排查，不要直接迁移。

## 5. 处理“数据库待迁移”（需授权）

以下只适用于本地开发 Compose。历史记录显示 2026-10-14 开发库曾从 0021\_resume\_wallet\_perms 升至 0031\_model\_usage\_reconciliation 并返回 ready 200；但 P284/P285/P288 运行态证据冲突，当前状态未知。执行前按上一节重新只读核对；本节步骤只在确有迁移待办、备份和明确授权后使用。已有用户的数据库不需要再次创建管理员。

1. 确认目标环境、数据库、维护窗口和备份负责人。选择实际受访问控制、加密且异机保存的备份目录；仓库内被忽略的目录本身不算受保护。先做只读预检，再创建真实归档：
   ```powershell
   .\deploy\backup-postgres.ps1 -ValidateOnly -DockerPath $iamDocker
   $iamBackupDir = '<已批准的受保护绝对路径>'  # 替换后执行
   .\deploy\backup-postgres.ps1 -OutputDirectory $iamBackupDir -DockerPath $iamDocker
   ```
   记录脚本输出的 `.dump` 绝对路径及同名 `.sha256` 文件。`-ValidateOnly` 不会生成备份；脚本生成归档后会检查 `pg_restore --list`，但这仍不能代替恢复演练。数据库归档不包含 `.env`、数据库 roles/global 或 OIDC 私钥，需按部署方案分别保管。
2. 用**刚生成的实际归档路径**在随机隔离库恢复，确认脚本核对 SHA-256、Alembic revision 和核心表成功；失败时停止迁移并检查保留的临时库：
   ```powershell
   $iamBackupFile = '<备份脚本输出的.dump绝对路径>'  # 替换后执行
   .\deploy\verify-postgres-restore.ps1 -BackupFile $iamBackupFile -DockerPath $iamDocker
   ```
3. 审阅[迁移影响与回退方案](部署与运维.md#4-迁移授权与回退)，记录目标 `current`/`heads`、归档标识、恢复结果和负责人，取得针对该环境与目标库的**明确迁移授权**。`0024/0025` 涉及旧注册挑战清理，`0026–0030` 只登记权限目录、不自动授予角色；不要把 `alembic downgrade` 当作通用回退。
4. **完成以上条件后**迁移。任一步失败即停止，不继续创建管理员或提交登录：
   ```powershell
   & $iamDocker compose --profile migrate run --build --rm migrate
   if ($LASTEXITCODE -ne 0) { throw '迁移失败，停止后续操作' }
   & $iamDocker compose up -d api console
   if ($LASTEXITCODE -ne 0) { throw '服务重启失败，停止后续操作' }
   & $iamDocker compose exec -T api alembic current
   & $iamDocker compose exec -T api alembic heads
   Invoke-WebRequest 'http://127.0.0.1:8002/api/v1/ready' -NoProxy -SkipHttpErrorCheck -TimeoutSec 5
   ```

确认 `current` 与 `heads` 一致、`ready` 返回 200 后，再测试登录。**仅全新空库且尚无平台管理员时**，在迁移成功后经本次初始化授权运行 `& $iamDocker compose --profile bootstrap run --build --rm bootstrap-admin`；修改引导环境变量不会重置既有账号密码。生产 Compose 的启动依赖包含 one-shot migration，须按[部署与运维](部署与运维.md)第 5 节发布流程执行。

```powershell
& $iamDocker compose up -d
& $iamDocker compose ps
& $iamDocker compose logs -f api
& $iamDocker compose down
```

