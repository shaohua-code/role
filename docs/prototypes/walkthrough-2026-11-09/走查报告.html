一、核心结论

1 个 P0：用户管理三个写接口（停用/锁定、重置密码、撤销会话）只判按钮码、无数据边界与目标层级保护，租户管理员可对平台超管账号执行停用、锁定与密码重置，构成完整的平台接管链。运行时坐实

6 个 P1：两处跨租户/跨层级读取、组织台角色 key 判权使应用级可管全租户组织、三组可选租户参数的列表接口无范围过滤、邀请任命无天花板、以及前端「/admin/roles 分页契约」未适配导致租户模式控制台初始化崩溃（浏览器实测白屏）。

整体判断：认证与 OIDC 链路、判权核心（ensure_codes/范围闸门/min_scope）、种子与迁移链、前端路由闭环均实现扎实且经运行时验证；缺陷集中在「用户管理写路径」与「可选 tenant_id 列表」两类数据边界遗漏，以及一次前后端契约演进（角色列表分页化）的前端遗漏。

二、P0 缺陷（必须立即修复）

P0-1 用户管理写接口无数据边界与层级保护 P0运行时坐实

三个接口均仅判 button.users.manage（L3 模板持有），随后对任意全局用户生效，无租户边界、无目标角色层级校验：

  • users.py:481 PATCH /admin/users/{id}/status —— 停用/锁定任意账号（含 L1 超管）
  • users.py:527 POST /admin/users/{id}/password —— 重置任意活跃用户密码并取得登录权
  • users.py:119 POST /admin/users/{id}/sessions/{type}/{sid}/revoke —— 撤销任意用户任意会话

运行时证据：l3-admin（演示租户租户管理员）对超管账号 PATCH status 空操作请求返回 200，证明守卫完全放行（未实际变更状态）。利用链：审计页对 L3 可见本租户事件的 actor_user_id → 用 user_id 重置 L1 密码 → 以 L1 登录 → 平台接管。同文件 list_users:344 / create_user:392 均有边界，写路径遗漏属实现疏漏。

修复建议：非超管须校验目标用户至少一个活跃成员身份落在自身数据边界内；并禁止非超管对持有 platform 类角色（platform.admin/tenant.admin）的账号执行写操作；补齐对应测试。

三、P1 缺陷

P1-1 用户详情与会话接口跨租户/跨层级读取 P1运行时坐实

users.py:46-106 list_user_sessions 与 users.py:269-332 get_user_profile 仅判 menu.users（L2/L3 均持有），无数据边界。运行时：L2、L3 均可读取超管完整档案（成员关系/角色绑定）并枚举其 19 条会话。建议补 ensure_tenant_in_actor_scope 逐成员身份过滤。

P1-2 组织台判权按角色 key，应用级可管全租户组织 P1运行时坐实

admin_authorization.py:24-43 has_organization_admin_access 对 L1 之外只认 CONSOLE_ADMIN_ROLE_KEYS = (tenant.admin, app.admin)，manage=True 不生效。任何持 app.admin 的应用级管理员可对宿主租户全部组织树增删改（organizations.py:163/204/260/329/386 全走此守卫），并可将任意成员置 departed（级联清除其全部角色绑定）——应用级越权至租户级，与 button.org.manage min_scope=tenant 直接矛盾。运行时：L2 建组织返回 201（已即时删除清理）。建议写路径改 ensure_codes('button.org.manage', tenant_id) 由 min_scope 自动收口，并补 departed 保护的回归测试。

P1-3 tenant_id 可选的列表接口无范围过滤

groups.py:59-81、invitations.py:29-50、models.py:23-54：不传 tenant_id 时判权 any-of 通过后查询全表，L2/L3 可跨租户枚举用户组、邀请邮箱、模型目录（endpoint/单价）。对照正确实现：tenants.py:48 与 model_usage.py:59-85 均已按 list_actor_management_tenant_ids 过滤。建议统一复用该边界。

P1-4 邀请角色任命无天花板

invitations.py:132-145 + auth.py:325-390：邀请兑换发角色未经 bind_role 式层级校验（access_control.py:523-534 有对照实现）。当前 L2 模板无 invitations.manage 码，属不可达后门，但与任命口径不一致，未来扩权即放大。建议创建邀请时复用任命层级校验。

P1-5 租户模式控制台初始化崩溃（白屏） P1浏览器坐实

App.vue:294-295：平台角色全局化后 GET /admin/roles 已分页化返回 {items:[...]}（access_control.py:212），前端租户模式角色字典仍按 Row[] 调 .filter → TypeError: roleRows.filter is not a function → initializeConsole 在 visitedPages/路由跳转前中断 → L3 登录后首次进入整页空白（仅页脚），二次点击侧栏才恢复。RoleManagement.vue:249-252 已用联合类型正确解析，此处遗漏。建议按同口径解析 items，并在浏览器回归登录路径。

P1-6 运营总览租户模式永不加载 P1浏览器坐实

App.vue:150 loadPage 仅 platform 模式执行；L2/L3 持 menu.overview（permission_kinds.py min_scope=app），侧栏可进入但指标永远显示「—」占位（截图 iam-walkthrough-05）。而后端 overview.py 对 L3 实际返回全域计数（3 租户/5 应用/9 用户，运行时证实）。两处口径需产品裁决：租户模式提供过滤后的统计，或隐藏统计区并给说明态。
