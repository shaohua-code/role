01Background

背景与问题

现行权限目录与四级角色体系在多轮迭代后暴露三类结构性问题，产品已裁决推倒重写。

现行目录 67 码 = 管理面 iam.* 27 + 业务面 40

P-1 命名不一致

role 与 app_role 语义易混、user 与 member 边界模糊，platform.overview / authorization.simulate 等「域.动作」式编码破坏三段式一致性。

P-2 第一段无信息量

全部 iam. 前缀，菜单分组、授权分组、收敛矩阵都要靠第二段二次映射。

P-3 历史数据混杂

多轮造数与调整后，角色目录与授权关系不再「样板干净」。

产品决策 · 已确认

编码与角色体系推倒重写平台侧权限编码与角色体系全部重写
历史数据绿场一键重置清零DeerFlow 业务试点资产一并清零，之后按新体系重新登记
UI 重新设计角色管理 / 权限编码页按新体系重新设计

04UI Redesign

UI 重设计（角色管理 + 权限编码页）

两页按新体系重新设计，全局码引用同步全量替换。

权限编码页

域总览统计卡带改为「五域 + 全部」六卡（platform / rbac / org / app / ops，账本式编号）；表格「权限域」列按新域名 + 色点；登记弹窗的编码校验提示更新为五域白名单（platform. / rbac. / org. / app. / ops. 管理面 + 应用命名空间业务面）。

角色管理页

作用域三卡文案与 kind 标签不变；「全部类型」筛选保留；配置权限弹窗左栏域导航改为五域（收敛矩阵同步映射）。

授权弹窗

收敛矩阵域 key 更新：租户角色隐藏 platform 域 + 业务码；应用角色隐藏 platform 域 + 治理组（rbac.role.* / rbac.permission.manage）+ 跨命名空间业务码；已持有码豁免规则不变。

全局

侧栏菜单 requiredPermissions、路由守卫、能力判定的码引用全量替换为新码（navigation.ts / capabilities.ts / 各页面 cachedHas 调用点）。
