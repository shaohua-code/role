模型目录与分发 · 概述

来源：《产品需求》§6.4 模型目录与分发、§3.2 节点收口、§7 页面关键状态 · 范围：模型治理 / 模型用量两个管理台页面 · 配额拦截（MODEL_QUOTA_ENFORCEMENT_ENABLED）默认关闭 · §6.4.1 模型统一接入与用量控制为后续专项，不在本原型范围。

背景与问题

业务应用的模型能力由平台统一供给：平台维护模型目录，按「平台 → 租户 → 应用」三级下发决定谁能看到、调用哪些模型。没有统一目录时，各应用自行维护模型清单与密钥，无法回收、无法审计、无法计量。本模块把目录维护、三级分发与用量账本收进管理台两个页面，并以审计保证每次下发与回收可追溯。

主用户与核心任务

角色授权范围在模型治理 / 用量中做什么不能做什么
平台超级管理员超管维护平台模型目录（新建 / 编辑 / 停用 / 删除）；将模型下发给租户并撤回；查看全域用量删除存在用量账目的模型；下发或回读凭证明文
租户管理员租户级将本租户已收到的模型下发给应用并回收；查看本租户用量新建或修改平台目录；下发本租户未收到的模型
应用管理员应用级查看本应用可见模型清单（只读）；查看本应用用量任何写操作

核心链路（P0）

  1. 超管在「模型治理」新建平台模型（标识、供应商、显示名、能力标签、单价、限流、凭证引用）。
  2. 超管将模型下发给租户；租户进入「已收到」范围。
  3. 租户管理员将已收到的模型下发给本租户应用；应用管理员在应用侧看到只读清单。
  4. 业务应用经 GET /api/v1/authorization/my-models 消费三级交集清单（契约见《应用对接》§9）。
  5. 受信网关上报用量，「模型用量」账本按租户 + 应用归属记账、估算费用、标记计量质量。
  6. 回收（软失效）或平台停用后，下游立即不可见；每次下发 / 回收 / 状态变更记审计。

完成条件

一个模型从建目 → 下发租户 → 下发应用 → 应用可见 → 产生用量 → 回收 / 停用不可见，全程在两个页面内完成且有审计可查；期间读取失败、空目录、空账本、待核对等状态均有明确呈现。

关键状态清单（§7 收口）

状态位置呈现要求
空目录 / 未收到模型 / 应用未下发模型治理（三视角各自空态）引导下一步动作，不显示空表格
空账本模型用量明确「暂无上报记录」
读取失败两页通用显式报错 + 重试，不得伪装成成功空态
待核对模型用量预留到期进入人工核对队列，核对前保守占额
下发关系计数与回收确认模型治理计数可点开关系弹窗；回收需确认且说明软失效语义

边界与假设

  • 配额拦截默认关闭：平台只记录与估算用量，不拦截调用；无币种字段、无失败原因字段。
  • 凭证只存外部引用（如 vault 地址），不回读、不下发；真实调用凭证由业务应用自持。
  • IAM 只管目录与授权，不做模型代理网关、供应商账单结算（§6.4.1 M01–M07 后续专项）。
  • 侧栏其余页面不在本原型范围，点击给出明确不可用提示。
  • [假设] 模型编辑时不回显凭证引用原文，占位提示「已保存（不回显）」，重新填写则覆盖。
  • [假设] 删除仅校验「存在用量账目」阻塞；下发关系存在但无用量时允许删除并级联清理关系（正式验收前需与后端确认）。

功能需求

按业务能力组织；每个章节右侧「原型入口」可直接驱动左侧原型到对应画面。

F1 · 平台模型目录（超管维护）

平台支持的模型全集由超管统一维护，是三级下发的唯一源头。目录行统一归属平台租户（slug=platform），所有按 ID 的目录 / 下发操作强制校验该归属，非平台目录行与不存在同样按 404 处理。

列说明
模型显示名 + 模型标识（key，全局唯一）
供应商 / 能力标签 / 单价 / 限流能力标签为 7 项标准集；单价未维护显示「未知」；限流为目录级 RPM / TPM
凭证引用仅存外部引用，不回读、不下发（列表中不展示原文）
状态启用 / 停用；停用 = 全链路立即不可见
下发租户关系计数，点击打开「下发租户」弹窗（F3）
操作编辑 / 下发租户 / 停用（启用）/ 删除，全部由 button.models.manage（仅超管）收口

边界：目录为空显示引导空态；读取失败显示错误面板与重试，不得伪装成成功空态。

原型入口

F2 · 新建与编辑模型（能力标签标准集 · 凭证引用）

新建与编辑共用同一表单抽屉；提交成功后刷新列表并记审计。后端对能力标签做白名单强制校验，前端只允许勾选标准集。

字段必填规则
模型标识（key）是全局唯一；重复提交返回 409 冲突提示
供应商是下拉选择
显示名是列表与 my-models 清单中的展示名
能力标签勾选配置标准集 7 项：chat 对话 / reasoning 深度思考 / thinking_output 思考过程输出 / tool_calls 工具调用 / json_output JSON 输出 / vision 视觉 / embedding 向量嵌入
单价否留空 = 费用记「未知」；当前无币种字段，费用仅作平台估算
RPM / TPM否目录级限流参考值
凭证引用建议填写仅保存外部引用；编辑时不回显原文，重新填写则覆盖；明文永不进入界面与响应
原型入口

F3 · 平台 → 租户下发与撤回

超管在目录行打开「下发租户」弹窗，勾选目标租户保存，差异更新下发关系。租户可见范围 = 平台目录 ∩ 租户下发，下发关系即授权唯一依据。

  • 撤回 = 软失效：保留下发关系供恢复与审计，租户侧立即不可见；再次勾选即恢复。
  • 保存后目录行「下发租户」计数即时刷新；下发 / 撤回记审计，与写操作同事务。
  • 存在将被回收的关系时，确认按钮变为「确认回收并记审计」，弹窗内给出软失效说明。
原型入口

F4 · 租户 → 应用下发与回收（软失效）

租户管理员（持 button.models.distribute，节点下限租户级）在「本租户收到的模型」列表行打开「下发应用」弹窗，勾选本租户应用保存。

  • 只能下发本租户已收到且平台侧仍启用的模型；只能选择本租户的应用（范围只能向下）。
  • 回收为软失效：保留关系供恢复与审计，应用侧立即不可见；恢复 = 再次勾选保存。
  • 下发 / 回收记审计，与写操作同事务。
  • 本租户未收到任何模型时显示「租户未收到模型」空态（对应 §7 模型 Tab 空态）。
原型入口

F5 · 三级交集可见性与应用只读清单

可见性唯一口径为三级交集，下发关系即授权唯一依据；业务码 / 应用资源树不参与模型判权。

应用可见模型 = 平台目录（启用） ∩ 租户下发（active） ∩ 应用下发（active）
租户可见模型 = 平台目录（启用） ∩ 租户下发（active）
  • 应用管理员对本应用模型清单只读，无任何写入口。
  • 回收或平台停用后立即不可见（验收标准 15）。
  • 业务应用以用户 token 调 GET /api/v1/authorization/my-models?client_id= 获取本应用可见模型；清单范围绑定服务端验签的 token 应用身份，client_id 仅作一致性校验，跨应用查询拒绝。/authorization/check 的 model.invoke 调用前检查按同一口径判定。
原型入口

F6 · 停用与删除阻塞

停用：需确认（「停用后该模型全链路立即不可见，含已下发租户与应用；历史用量保留」）；停用后可重新启用，状态变更记审计。

删除：存在用量账目记录的模型禁止删除，弹窗明确提示改用「停用」，避免误删审计与账目；无用量账目的模型删除前需确认，删除后下发关系级联清理。删除操作同样校验目录行的平台租户归属。

原型入口

F7 · 用量账本与数据边界

受信网关使用专用上报密钥（≥32 字符）写入用量事件；平台不存 Prompt 与模型响应正文。账本按租户 + 应用归属，列表按操作者数据边界过滤：超管全域、租户级限本租户、应用级限本应用。

字段说明
时间 / 租户 / 应用 / 模型归属三元组 + 目录模型引用
输入 / 输出 tokens按 Provider 可信 usage 记录
费用估算按目录单价估算；未维护价格记「未知」；当前无币种字段、无失败原因字段
计量质量actual 实际 / estimated 估算 / unknown 未知
状态已结算 / 待核对（F8）

边界：支持按租户 / 应用 / 模型筛选；空账本明确「暂无上报记录」；读取失败显式报错并提供重试，不得伪装成成功空态。

原型入口

F8 · 待核对队列与配额拦截关闭口径

页面常驻提示：配额拦截默认关闭，平台仅记录与估算用量，不拦截模型调用。

  • 预留（保守占额）到期后进入人工核对队列，不自动收费、不自动释放；核对前继续保守占额。
  • 「待核对」标签页单独列出未决预留；行内「人工核对」入口展示队列语义说明（完整的对账、更正与证据链能力属 §6.4.1 M06 后续专项，本期内不实施）。
  • 配额 enforcement 上线须满足《产品需求》验收标准 10 的产品与运维门槛并获明确授权，本原型不提供开关。

共享规则

本页集中定义权限、可见性、状态与审计口径；功能章节不再重复。

权限与节点收口

能力节点 / 范围超管租户管理员应用管理员

租户下发 / 撤回button.models.manage可不可不可

可见性与失效口径

  • 可见性 = 三级交集（见 F5 公式）；下发关系是授权唯一依据。
  • 回收 = 软失效：关系保留（可恢复、可审计），下游立即不可见。
  • 平台停用 = 全链路立即不可见；重新启用后按既有下发关系恢复可见。
  • 平台目录行归属平台租户（slug=platform）；跨归属或不存在一律 404，不泄露存在性。

对象状态含义

revoked（软失效）不可见但保留，可恢复
