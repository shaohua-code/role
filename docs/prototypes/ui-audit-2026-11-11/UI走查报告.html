〇 · 走查维度框架

本轮按八个维度系统走查，每条发现都标注归属维度：

  • A 设计语言 — token 纪律、语义色边界、明暗主题一致性
  • B 布局空间 — 4px 间距节奏、栅格断点、对齐、密度
  • C 组件工艺 — 表格/表单/弹窗/分页/标签的跨页一致性与细节完成度
  • D 导航与信息架构 — 侧栏、页头体系、编号章节、面包屑
  • E 反馈与状态 — loading / empty / error 三态完整性与观感
  • F 可访问性 — 对比度、焦点、键盘路径、触控目标
  • G 响应式 — 笔记本/窄屏降级、滚动模型
  • H 文案微打磨 — 歧义句、排印口径、语言统一

二 · P0（破坏可用性，立即修）

编号维度发现 · 根因 · 建议
U1F 暗色主题侧栏非激活项近乎隐形。深色下分组标题与全部菜单项呈暗灰压黑底，/overview 与 /users 均复现，是全项目当前最严重的可访问性缺陷。
根因方向：侧栏菜单色未随暗色 token 提升（待修时定位 AppSidebar / .mgmt-sider 的菜单 token）。
建议：暗色下非激活项文字 ≥ --color-text-secondary（#a1a1aa），hover 提到 primary；一个 token 收口全站。
U2D /model-usage 空态编号仍跳 03（上轮 M1 未闭环）。空态合并带占「02」，后续「04 待核对 / 05 账目」不变 → 序列 01→02→04→05。
建议：编号改为「位置序」动态计算——空态下待核对=03、账目=04；有数据时恢复 04/05。另：汇总卡内 01–05 编号与节编号双体系打架，去掉卡内编号（见 U20）。
U3G 列表页固定高度滚动模型在笔记本视口（720p）系统性劣化。/users、/tenants、/roles 三页同症状：表体固定 calc(100vh - 430px) 仅剩约 3.5 行、行被滚动区拦腰切断、横向滚动条贴行、固定操作列独立滚动形成「表内套表」割裂感。
建议：AdminListPage 列表保留工具条+分页常驻的前提下，给 y 加下限 calc(max(360px, 100vh - 430px))；列宽重新预算（users 姓名列 130 过窄、roles 权限列压缩换行）；长期方向 = 工作台已验证的「内容自然生长 + 单一滚动上下文」。

三 · P1（一致性硬伤，本迭代修）

编号维度发现 · 根因 · 建议
U4A AdminFilterPanel 使用 Tailwind 默认 slate 色板（border-slate-200/70 bg-slate-50/60）——蓝底灰混入 zinc 中性体系，浅色下淡到近乎隐形（audit 页「空白圆角条」的观感来源），暗色全靠 style.css override 兜底。
建议：换 var(--color-border) / var(--color-bg-subtle)，删除暗色补丁。
U5C 工具栏圆角倒置：toolbar rounded-2xl(16px) 嵌在卡片(12px)内，内层比外层更圆，违反嵌套圆角法则。一处修（AdminTableToolbar → rounded-xl）全站生效。
U6C 分页三种形态 + 当前页两种皮肤：audit/roles 带「共 N 条」，users/tenants/groups/invitations 无；pageSize 默认 10 与 20 混用；audit 当前页黑底实心 vs 组织台白底描边（待截图复核）。
建议：AdminListPage 统一注入 showTotal 与 pageSizeOptions；皮肤差异跑一次 DOM 对比定位。
U7E 空表格仍渲染全宽横向滚动条（groups / invitations / 主题版本历史 / 待核对表 ×2），空态重心被一条死滚动条带散。
建议：一条全局 CSS——.ant-table-empty .ant-table-content::-webkit-scrollbar { display:none }（含 scrollbar-width:none）。
U8A 环形图暗色两段隐形：D2 石墨墨阶在暗色翻转后，最小两段拿到 #3f3f46/#2e2e32，压在 #18181b 卡上不可见（小值+最暗双重劣势），图例「租户」同隐。
建议：暗色下墨阶设亮度下限（最深到 zinc-600 #52525b），或 palette() 按 data-theme 切换两套墨阶。
U9F 外观面板不支持 Esc 关闭（实测），键盘路径缺失；另「外观」描边按钮与相邻「修改密码/退出」纯文本同栏混排。
建议：Popover 补键盘关闭；顶栏按钮统一为纯文本 + 分隔线。
U10D eyebrow 语言混用：11 个活跃页为英文装饰语，仅 /roles 用中文「平台角色」（RoleManagement.vue:667）。
建议：改为「ROLE DIRECTORY」，与其余页统一。
U11B 5 卡指标带在 lg 档（1024–1279）呈 3+2 孤位：sm:grid-cols-3 xl:grid-cols-5 跳过 lg，第二行右侧留整块空位（/overview 与 /model-usage 两处同源）。
建议：加 lg:grid-cols-5（两行改动）。
U12B 用量汇总脚注观感溢出：mono 长行「成功 0 · 失败 0 …」横穿卡底下方，读作悬浮裁切文字。
建议：去 mono/字距，改 text-xs muted 常规说明行，左对齐网格起点。
U13C 审计页操作者 UUID 截断形似乱码（三行同值切在连字符上）。
建议：该列用 AdminMonoValue + 复制悬浮，或加宽至 210。
U14A 深色次级按钮两套皮肤（/users「刷新」白底 vs /overview「刷新概览」深底）+ 顶栏「外观」chip 深色下常亮。
建议：跑一次暗色 DOM 对比定位 token 差异；预期统一走 antd darkAlgorithm。

四 · P2（打磨项，批量收口）

编号维度发现与建议
U15H「刷 新」antd 两字自动加空格 vs「＋ 新建」全角加号混用；「＋」前缀仅列表页携带。统一按钮排印口径（接受 antd 空格、加号统一用图标）。
U16C应用台角色 Tab 工具栏左槽完全空白（控件全挤右段），组织台同位是搜索框——双工作台骨架不对齐。给 RolesTab 左槽补一个语义控件（如角色类型筛选）。
U17C邀请页租户下拉当前值「全部租户」以占位灰渲染，与 groups 页黑色实值形成同组件两态观感。给「全部」一个真实 value。
U18A空态 emoji 清晰度三态（清晰/极淡/近空白），彩色 🤖🎨📊 与黑白轻奢体系冲突。建立 emoji 选用规范（高对比、优先中性图形），AdminEmpty 加统一底衬。
U19H应用台说明「权限码管管理台菜单/按钮显隐」连读歧义（管+管理台），且折行把「业务端」拆断。改「权限码控制管理台菜单/按钮显隐 · 接口鉴权看角色 · 资源树只管业务端」。
U20Dgroups 页存在全站唯一常驻 info 横幅；汇总卡内编号与节编号双体系。横幅并入 hint 气泡；卡内去编号。
U21C弹窗宽度 8 种散值（680/720/760/800/820/980）。收敛为三档：640 / 800 / 960。
U22C/themes：色板方块直角且与输入框不齐、分段控件右端直角不对称、卡头分隔线有无不一致、「欢迎文案」无占位。
U23D面包屑混排（「平台」描边 chip + 二级纯文本）；模拟器页脚免责与顶部 alert 文案重复。
U24Csticky 操作列与表体存在纵向色差接缝（浅/深主题均可感知）。统一 fixed 列背景 token。
U25F侧栏折叠图标对比度低；侧栏分组展开出现内部滚动无渐隐提示；停用 tag 灰字对比偏低。
U26B主按钮阴影无口径（「新建模型」有偏移阴影、「预演授权判定」无）。定一条：主按钮统一无阴影或统一 shadow-sm。
U27B列宽微调：/users 姓名列 130 过窄（富余宽度下过早截断）、组织台成员姓名列同理；成员/应用计数列过宽倒挂。
U28E鉴权模拟：4 个必填下拉无「请选择」占位，首访无从下手；「解析数据范围」开关结构与触控目标同 /themes 不一致。
U29C工作台详情头缺席页头体系（应用台「名称+长描述」vs 组织台「名称+灰标」两种结构），与顶层页 eyebrow+竖条体系脱节。
U30A「统计口径…」等 11px 浅灰说明对比约 2.3:1，低于 WCAG 建议下限；关键口径文字至少用 text-secondary。

五 · 核实后不修（避免过度设计）

结论说明
有意设计授权范围墨阶层级：走查中「租户级实心/描边不统一」的观感来自 D5 的刻意设计——超管=实心墨（最高权重）＞租户=重描边＞应用=细描边＞成员=虚线。保留。
观察误差表头截断「创建时/权…」：列宽 160/140 足够四字表头，疑为固定列遮挡处的读图误差；已列入 U3 修复时的回归核对点，不单独立项。
合法回退裸 hex 残留：全部为 echarts cssVar 回退值与 OIDC 主题数据默认值，非 UI 硬编码。合规。
环境相关滚动条箭头样式：Windows Fluent overlay 滚动条会忽略 ::-webkit-* 定制；CSS 已有 thin+scrollbar-color 方案，按环境呈现，非代码缺陷。
