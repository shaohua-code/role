## 五级平台角色（写死，不可自创）

| 级别 | 角色编码 | 含义 |
| --- | --- | --- |
| L1 | `platform.admin` | 平台管理员，全局最高 |
| L3 | `tenant.admin` | 租户管理员 |
| — | `apps.admin` | 多应用管理员 |

- 应用角色可挂：操作者可见的租户/应用**管理码** + 本应用**业务码**。
- 已作废（仅存于历史记录，禁止新用）：旧 `iam.*` 码、`platform.super_admin`、`tenant.org_admin`。

## 管理面判权单元：菜单/按钮节点码

admin 面板**逐路由**按菜单/按钮节点码判权（`menu.*` / `button.*`）：

- 侧栏认菜单节点，页内写按钮与接口映射认按钮节点；每个节点带 `min_scope` 授权下限（只能授予不低于自身范围的角色）。
- 权威码表：`backend/app/services/permission_kinds.py`（`MENU_CATALOG` / `BUTTON_CATALOG` / `MENU_BUTTONS`），与 `docs/产品需求.md` §3.3 保持一致。
- **业务权限码强制 data_scope**：业务类权限必须携带数据范围约束。
- 前端路由/按钮按 capabilities 裁剪显隐；后端接口用 `rbac_guards.py`（`ensure_codes` / `ensure_scope`）与 `admin_authorization.py` 的守卫判权。前端码不可信，不是安全边界。
- 模型判权例外：`model.invoke` 按三级下发关系判定（产品需求 §6.4），业务码/资源树不参与。
- 已废弃（仅存于历史记录，禁止新用）：旧五域 27 码目录（`platform.*` / `rbac.*` / `org.*` / `app.*` / `ops.*`）。

## 改权限相关代码的必检清单

1. 新增/修改节点码 → 同步 `permission_kinds.py`（MENU_CATALOG / BUTTON_CATALOG / MENU_BUTTONS）+ `docs/产品需求.md` §3.3（见 [05-常见任务/新增权限码.md](../05-常见任务/新增权限码.md)）
2. 角色计算 → 只改 `effective_roles.py`，并确认没有旁路实现
3. 接口判权 → 用现成守卫（`rbac_guards.py` 的 `ensure_codes` / `ensure_scope`、`admin_authorization.py`），不要手写 `if role == ...`
4. 前端显隐 → 按 capabilities 返回的节点码裁剪；前端码不是安全边界
