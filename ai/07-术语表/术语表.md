# 术语表

| 术语 | 含义 |
| --- | --- |
| IAM | Identity and Access Management，身份与访问管理，本项目主体 |
| 绿场（greenfield） | 方案 A：从零重建的权限体系（区别于在旧系统上改造） |
| 租户（tenant） | 顶层隔离单位，租户管理员为 L3 `tenant.admin` |
| 组织（organization） | 租户内的组织架构节点，树形，CRUD 在组织工作台 |
| 应用（application） | 接入 IAM 的业务应用，目录 CRUD 在应用工作台 |
| 资源树 | 应用下的资源层级结构，正式能力 |
| 平台角色 | 五级写死：L1 `platform.admin` / L3 `tenant.admin` / `apps.admin` / L2 `app.admin` / L4 `app.member` |
| 应用角色 | 挂在具体应用上的角色，可含管理码 + 业务码 |
| 权限码 | 管理面为菜单/按钮节点码（`menu.*` / `button.*`），权威码表在 `services/permission_kinds.py`（MENU_CATALOG / BUTTON_CATALOG）与 `docs/产品需求.md`；业务面为应用业务码。旧五域 27 码（`platform.*` / `rbac.*` / `org.*` / `app.*` / `ops.*`）已下线，仅存于历史记录 |
| 管理码 | 应用角色上挂的、操作者可见的租户/应用管理类权限码 |
| 业务码 | 应用角色上挂的本应用业务权限码，强制 data_scope |
| data_scope | 数据范围约束，业务权限码必带 |
| 工作台 | 侧栏一级分组：应用工作台 / 组织工作台，目录 CRUD 主入口 |
| 高级管理 | 侧栏一级分组：平台角色、权限编码、用户组等独立列表 |
| OIDC Provider | 后端对外提供的单点登录能力，代码在 `backend/app/api/v1/oidc_provider/` |
| 后通道登出（backchannel logout） | OIDC 登出联动机制，`services/backchannel_logout.py` |
| 有效角色（effective roles） | 用户最终生效的角色集合，唯一实现在 `services/effective_roles.py` |
| 上线门禁 | 特定能力（配额 enforcement、公开注册等）上线前必须满足的管控条件 |
| 受保护备份 | 数据库迁移前必须做的备份，且需用户明确授权 |
| 活文档 | `docs/` 下四份持续维护的文档（产品需求 / 应用对接 / 部署与运维 / 项目启动） |
| CHANGELOG | 根目录 `CHANGELOG.md`，每次工作的事实记录，未验证写"未运行" |
