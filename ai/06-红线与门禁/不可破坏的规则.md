# 不可破坏的规则（红线与门禁）

> 动手前必查。违反任何一条 = 任务失败。

## 范围红线

1. **本阶段只维护** IAM 管理台前端 + 绿场后端
2. **不做** DeerFlow / 业务项目接入联调；DeerFlow（若在 `D:\project\deer-flow`）不做对接或清理以外的改动
3. `frontend/src/views/_archive/`（含 integration/）是归档区：**禁止恢复、禁止引用**
4. 不创建后台自动任务；日常交接不自动触发全项目审计

## 安全红线

1. 数据库迁移前：**受保护备份 + 用户明确授权**，二者缺一不可
2. `ALLOW_BOOTSTRAP_EMAIL_BYPASS` 生产环境必须保持 `false`
3. 配额 enforcement、公开注册遵守上线门禁（未开门前不得绕过）
4. 真实密钥 / `.env` 不入库；敏感数据落审计前必须过 `access_log_redaction.py` 脱敏
5. 认证流程必须包含邮箱验证

## 架构红线

1. 五级平台角色**写死**：L1 `platform.admin` / L3 `tenant.admin` / `apps.admin` / L2 `app.admin` / L4 `app.member`，不得自创角色
2. 有效角色**只认** `services/effective_roles.py` 的实现，禁止旁路
3. admin 面逐路由按五域权限码（27 码）判权，前后端同码
4. 业务权限码强制 data_scope
5. 已作废概念禁止复活：旧 `iam.*` 码、`platform.super_admin`、`tenant.org_admin`
6. IA 固定：侧栏 = 应用工作台 / 组织工作台 / 高级管理；应用与组织目录 CRUD 只在工作台；资源树是正式能力

## 工程红线

1. 有通用组件必须先用，禁止重复造轮子
2. 页面必须 `文件夹/index.vue` 写法；关联文件放同一文件夹
3. 前端 100% Tailwind 工具类，禁止原生 CSS / 自定义 class / `!important`
4. 每次工作结束前更新 `CHANGELOG.md`，未运行的验证如实写"未运行"
5. 遵守 `docs/产品需求.md` 的 UI 硬规则与验收条件
