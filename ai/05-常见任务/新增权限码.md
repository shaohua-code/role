# Playbook：新增权限码

> 权限码是全系统安全基线，改动必须双源同步，缺一不可。

## 权威双源

1. `docs/产品需求.md` §3.3（管理面唯一目录 = 菜单/按钮树；业务面为应用业务码）
2. `backend/app/services/permission_kinds.py`（MENU_CATALOG / BUTTON_CATALOG 权威码表）+ `backend/app/services/rbac_guards.py`（判权守卫）

## 步骤

1. **确认必要性**：能否用现有码覆盖？能用就不新增
2. **确定种类**：管理面新页面/按钮 → `menu.*` / `button.*` 节点（带 min_scope 授权下限）；业务权限码必须带 data_scope
3. **后端**：`permission_kinds.py` 注册节点（MENU_CATALOG / BUTTON_CATALOG / MENU_BUTTONS），接口用 `rbac_guards.py` 判权
4. **文档**：`docs/产品需求.md` 权威码表同步
5. **前端**：侧栏/按钮按 capabilities（节点码）裁剪显隐
6. **角色开通**：需要挂到哪些角色 → `services/role_provisioning.py` / `effective_roles.py` 路径确认
7. **收尾**：CHANGELOG 记录 + 验证结果

## 禁止

- 禁止复活已作废码：旧五域 27 码目录（`platform.*` / `rbac.*` / `org.*` / `app.*` / `ops.*`）、`iam.*`、`platform.super_admin`、`tenant.org_admin`
- 禁止只在后端或只在文档单边添加
- 禁止在 `effective_roles.py` 之外实现角色 → 码的映射
